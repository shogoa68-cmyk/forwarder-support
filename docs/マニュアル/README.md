# マニュアルの原稿（ここを直すと、アプリの「📖 マニュアル」が変わります）

- 1 章 = 1 ファイル（`NN-名前.md`）。ファイルの先頭の `---` で囲んだ部分が章の設定です。
- 直したら `node scripts/build-manual.js` を実行し、`フォワーダー支援/data/manual.js` を作り直します（手で直さない）。
- 機能の改修を見張る：`node scripts/build-manual.js --check` を実行すると、
  ①まだ説明の無い画面 ②説明を書いた後にプログラムが変わった章（`watch` のファイルが `updated` より後に変更された章）を一覧にします。
  見直したら、本文を直して `updated` を今日の日付にします。手順は `.claude/commands/update-manual.md`。
- **公開リポジトリです**：お客様名・社内の情報・実際の金額は書かないこと（例は「○○商事」「USD 1,200」などの架空の値）。

## 章の設定（先頭の --- の中）

| 項目 | 意味 |
|---|---|
| `id` | 章の名前（英数字とハイフン）。リンク `[文字](#manual:id)` で使う |
| `title` | 章の題名 |
| `group` | 目次のまとまり（はじめに／見積を作る／進行・共有／マスター・実績／困ったとき／管理者向け） |
| `order` | 並び順（小さい順） |
| `level` | 初級／中級／管理者 |
| `open` | 「この画面を開く」で開く画面（`.cat-btn` の `aria-controls`。例 `tab-quote-make`）。無ければ省略 |
| `covers` | この章が説明している画面（カンマ区切り）。未記載の画面の判定に使う |
| `watch` | この章に関係するプログラム（`フォワーダー支援/` からの相対パス・カンマ区切り）。ここが変わると「見直しが必要」になる |
| `updated` | 最後に本文を見直した日（YYYY-MM-DD） |

## 本文で使える書き方

`## 見出し`・`### 小見出し`・段落・`- 箇条書き`・`1. 番号つき`・`**太字**`・`` `ボタン名` ``・`> 💡 ひとこと`（囲みの注意）・`[文字](#manual:章のid)`（別の章へのリンク）。

## 練習（AI トレーナーのレッスン）

本文の中に次の形で書くと、章に「▶ 練習する」が付き、画面の上で 1 歩ずつ案内します。

````
```lesson
id: first-quote
title: 見積を 1 件作ってみる
open: tab-quote-make
step: .qpd-newcard | ここを押すと、新しい見積を始められます。
click: #qf-customer | お客様の名前を入れてみましょう。（押すと次へ進みます）
step: - | 画面のどこにも印を付けない説明だけの手順は「-」
```
````

- `step:` は［次へ］で進む手順、`click:` はその場所を押すと自動で次へ進む手順（［次へ］も使える）。
- 場所（セレクタ）が画面に見つからないときは、説明だけを画面の中央に出します（止まりません）。
