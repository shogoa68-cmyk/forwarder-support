## 1. 目的と大方針
- **目的**：機能が増えて情報が多くなった画面を、**業務知識はあるが IT に弱い新規ユーザー**にも分かりやすくする。ただし **機能は壊さない**（隠す＝DOM に残す。保存・計算は継続）。
- **進め方**：Claude Design（別ツール）が出す案を、こちらで実アプリの構造に合わせて取り込む。**切替式・既定オフ・元に戻せる**ことを守る（現行 CSS は書き換えず、テーマ層で上書き）。
- **最終形**：全ユーザーを新デザイン（Industry）＋かんたん表示へ**強制切替**する予定（時期は未定。下記 §4）。それまで現行デザイン（classic）は退路として維持。
- **ユーザーの意思決定（確定済み）**
  - かんたん表示：**全ユーザーの既定を「かんたん」へ**（検証後に切替。初回に案内を出す）。現在の既定は「詳細」。
  - 更新日（行の `lu`）：**行・サブコン／パターン見出しの両方で CSS で隠す**（データ・機能は残す）。
  - **機能の統廃合は、デザイン統一の後**（デザイン段階では機能を消さない）。
  - 自動保存は廃止済み。
  - Industry 専用の見た目（テーブル行レイアウト等）は Industry 層のみ。文言変更や部品の移動など共通で良いものは共通側。

## 5. 実装の要点（技術メモ）
### テーマの層構造
- `css/tokens.css`・`css/style.css`・`css/quote.css`：現行（classic）。
- `css/theme-industry.css` / `theme-industry-doc.css`：**生成物（手編集禁止）**。`node scripts/build-industry-theme.js` が、Design の CSS（`docs/design-handoff/industry/css/`）と現行の差分から作り、セレクタを `:where(html.theme-industry)` で包む。`--check` で最新か検証。**現行 CSS（style/quote/quote-pdf/tokens）や Design 側の CSS を変えたら必ず再生成**。
- 取り込み順（`build-industry-theme.js` の `addons`）：`quote-table-industry` → `quote-hierarchy-industry` → `blueprint-industry` → `quote-table-fb03` → `quote-row-stage1-industry` → `quote-row-stage2-industry` → **`code-overrides-industry`（こちらで書く補正。最後）**。
- Design の CSS は**そのままでは実構造に合わないことが多い**。`code-overrides-industry.css` に補正を足す（理由を必ずコメントに書く）。
- 切替：`<html class="theme-industry">`（保存 `forwarderTheme_v1`、`?theme=`）。`js/tweaks.js`・`index.html` 冒頭の early script。
- かんたん表示：`<html class="mode-simple">`（保存 `fwd.uiMode`、`?mode=simple|detail`）。`js/ui-mode.js`・`css/simple-mode.css`・`cloud.js`。

### 見積テーブルの行（`<template id="row-tpl">`、`index.html`）
- セル：`check` / `handle`(つまみ＋`.row-acts`) / `catsv`(`.stk`: cat・sv・pt) / `name`(品名・`.w-note-row`・`.w-valid`・`.w-updated`・`.master-actions`・`.row-detail-panel`) / `qty`(`.qty-wrap`) / `ccy` / `price`(`.stk-price`・`.row-mode-btns`) / `tax` / `subtotal` / `profit`。
- `tbody` の子は3種類：**明細行**（`id="row-N"`、`data-type` も `data-virtual` も無い）／**付随行**（`data-type=subtotal|remark`。リマークは `data-parent-id` で明細の子）／**仮想行**（`data-virtual="1"`。`renderSubconGroups` が毎回消して作り直す）。**行を増やす実装（別 `<tr>` のパネル等）は危険**。
- 小計・利益は `row.js calc()` が `.st-main/.st-sub/.st-state`、`.pr-main/.pr-sub` の div で書き出す。
- **Industry のときだけ**、`js/quote/row-layout.js` が `.w-valid`・`.row-mode-btns`・`.pct-group`・`.row-cd` を「その他 ▾」パネルへ要素ごと移し、classic に戻すと元へ戻す（`id`・`onclick`・`data-*` は不変）。状態チップ・使用中バッジ・`tr[data-ccy-diff]`・パネル開閉（Esc／外側クリック／上向き `is-flip`）もここ。
- `↑↓` キー移動は `data-col`（0 cat／1 nm／2 qty／2u unit／3 pc／3b bc／4 pp／5 mk／6 nt）。パネル内の入力欄には `data-col` を付けない。
- 表は `table-layout:fixed`。**列幅は `<th style="width">` のインラインが決める**ので、CSS で変えるときは `!important`（`code-overrides` の th 幅、合計 992px。画面幅 1400px で表の領域が約 998px のため Design の 1040px から縮めた）。`#quoteTable{min-width}` も合わせて 992px。
- 行の高さは 120px（32px×3段＋段間4px×2＋上下余白8px×2。Design の 116px は計算違い）。
- 客先モード（`#quoteTable.customer-mode`）は社内情報（状態チップ・「その他 ▾」・CD）を隠す補正済み。

### その他の注意
- ファイルに **NUL バイトが混じることがある**：`grep -a`／Python（`errors='surrogateescape'`）で扱う。
- 現行の隠す方針：**消さずに隠す**。`id`／`onclick`／`data-*`／JS が付け外しする class は残す（`scripts/check-ui-contract.js` が基準 `docs/ui-contract.json` と照合）。意図した削除のときだけ `--update`。
- `見積支援/` は読み取り専用（編集しない）。
- 画像・資料に **実データ（実際の航路・サブコン名・金額）が写る場合は、リポジトリに置かず zip のみで Design に渡す**。

## 6. Design との協業フロー（手順）
1. ユーザーが実画面で気づいた点を **「いくつか報告するので何もアクションを起こさず控えて」** と前置きして順に報告する → **記録だけ**する（実装しない）。
2. 「Design へのフィードバックを作成し、zipで渡して」と言われたら、`docs/design-handoff/requests/NN-題名.md` を書く（番号は連番。現在 08 まで）。含めるもの：課題（画像付き）、実アプリの構造（セル・クラス名・どの JS が触るか）、**守る条件**（`id`/`onclick`/`data-*` 維持、機能の廃止はしない、隠す項目も DOM に残す、キーボード操作、詳細／かんたん両対応、客先向け出力は対象外）、依頼事項、成果物の形式。画像は zip にのみ入れる。**`SendUserFile` で zip を渡す**。
3. ユーザーが Design の返信 zip（`Forwarder_design_system_kickoff_N.zip`）を渡す → 展開して**旧版との差分**を確認 → **レビュー結果を報告して、「進めて」の指示を待つ**（指示があるまで実装しない）。実構造と合わない点は、Design への返信（文書）にして再依頼する。
4. 「実装を進めて」→ 実装 → 検証（§7）→ **コミット・push して止まる** → 「マージして」を待つ。
- 迷う判断（優先順位・統廃合・既定の切替）は **ユーザーに確認**。Design が出した案の採否は、こちらで決め打ちせず、論点と推奨を添えて報告する。

## 7. 開発・検証ワークフロー
- **コミット**：日本語の題＋本文に「## 動作確認」。末尾に次の2行（システムの指示で変わることがあるので、その時点の指示を優先）。
  ```
  Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/<session>
  ```
- **PR とマージ**：**ユーザーが「マージして」と言うまで PR を作らない・マージしない**。PR 本文の末尾は `🤖 Generated with [Claude Code](https://claude.com/claude-code)` と空行＋セッション URL。**squash マージ** → ブランチを `origin/main` に合わせ直す（`git fetch origin main && git checkout -B <branch> origin/main`、`git push --force-with-lease`。マージ済みの履歴のみなので安全）→ **デプロイを確認**。
- **GitHub 操作**は `gh` CLI ではなく MCP ツール（`mcp__github__*`。ToolSearch で読み込む）。デプロイ確認は `actions_list` の `list_workflow_runs`、`resource_id=deploy.yml`（Test ワークフローではなく **Deploy to GitHub Pages**）。`waiting`／`queued` のことがあるので、完了まで確認して報告する。
- **検証（変更のたびに）**
  - `node scripts/build-industry-theme.js --check`（CSS を変えたら先に再生成）
  - `node scripts/check-ui-contract.js`
  - `node scripts/ui-smoke.js` と `--theme both`（主要操作 12 項目）
  - `THEME=1 node scripts/design-tests/table-test.js` ほか（[scripts/design-tests/README.md](../scripts/design-tests/README.md)）
  - 見た目：`scripts/sample-table-shots.js`／`sample-editor-shots.js`／`sample-dashboard-shots.js`（架空データ。`THEME=1`／`MODE=simple`）で前後比較の画像を作り、必ず目で見る。
  - Playwright 実行時は `export NODE_PATH=$(npm root -g)`（chromium は `/opt/pw-browsers/chromium`）。
- 既知：`ui-smoke.js --mode simple` は変更前から `selectOption` でタイムアウトする（かんたん表示では一部の操作が前提外。今回の変更とは無関係）。
- ロードマップ（`フォワーダー支援/roadmap.html`）は `docs/アイデア台帳.md` から生成。台帳を編集したら `node scripts/build-roadmap.js`。
