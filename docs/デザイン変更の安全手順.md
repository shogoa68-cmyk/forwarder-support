# デザイン変更の安全手順

デザイン（見た目）を変えるときに、機能が壊れていないかを確かめるための手順。
このアプリは「画面の部品名（id・class・data-*・onclick の関数名）」で見た目と機能がつながっているため、
見た目の改修でこれらが変わると、ボタンが反応しなくなる等の不具合になる。

## 道具（リポジトリ直下から実行）

| 目的 | コマンド |
|---|---|
| 部品名のつなぎ目が壊れていないか | `node scripts/check-ui-contract.js` |
| 主要操作が動くか（動作確認） | `node scripts/ui-smoke.js` |
| 主要画面のスクリーンショット保存 | `node scripts/ui-smoke.js --shots <フォルダ>` |
| 2つの保存結果を比べる | `node scripts/ui-smoke.js --compare <変更前> <変更後>` |
| 変更前の状態を別フォルダに取り出して撮る | `git archive HEAD フォワーダー支援 \| tar -x -C <フォルダ>` のあと `node scripts/ui-smoke.js --root <フォルダ> --shots <before>` |

- 御見積書は長いため、文書だけを別の領域に描き出して全体を撮る（通常・発生時のみ／参考情報／概算の注記・FCL案/LCL案の併記・英語出力の3種）。
- スモークテストには Playwright と Chromium が必要。`NODE_PATH` に playwright の node_modules、`CHROMIUM_PATH` に Chromium を指定できる。
- スクリーンショットは固定の日付・サンプルデータ・固定サイズで撮るため、変更が無ければ何度撮っても差は 0。
  ただしフォント等が環境で違うと差が出るので、**変更前後は同じ環境で撮る**（基準画像はリポジトリに置かない）。
- `docs/ui-contract.json` は「壊してはいけないつなぎ目」の基準。意図して部品名を変えたときだけ
  `node scripts/check-ui-contract.js --update` で作り直す（その差分をレビューする）。

## 手順
1. **変更前**：`node scripts/ui-smoke.js --shots <before>` で現在の見た目を保存（同時に動作確認も通る）。
2. 別ブランチでデザインを変更する（原則 CSS のみ。HTML を触るときは id・class・data-*・onclick を残す）。
3. **変更後**：
   - `node scripts/check-ui-contract.js` … NG が出たら、そのつなぎ目を直す（または意図した変更なら基準を更新）。
   - `node scripts/ui-smoke.js --shots <after>` … 動作確認がすべて OK であること。
   - `node scripts/ui-smoke.js --compare <before> <after>` … 差のある画面が意図した範囲か、差分画像（`<after>/diff/`）で確認。
4. 問題が無ければ PR → マージ。問題があれば、そのブランチ／PR を取り消す。

## 既知の未実装（今回の変更とは無関係）
HTML から呼ばれているが JS に定義が無い関数：`quickLookup`（追跡）・`freetimeLookup`・`judgeIncoterms`・`resetIncoterms`。
基準ファイルには「未定義」として記録済みなので、デザイン変更の失敗としては数えない（`docs/バグ台帳.md` の既知の不具合）。
