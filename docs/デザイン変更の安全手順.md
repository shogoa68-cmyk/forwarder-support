# デザイン変更の安全手順

デザイン（見た目）を変えるときに、機能が壊れていないかを確かめるための手順。
このアプリは「画面の部品名（id・class・data-*・onclick の関数名）」で見た目と機能がつながっているため、
見た目の改修でこれらが変わると、ボタンが反応しなくなる等の不具合になる。

## 道具（リポジトリ直下から実行）

| 目的 | コマンド |
|---|---|
| 部品名のつなぎ目が壊れていないか | `node scripts/check-ui-contract.js` |
| 主要操作が動くか（動作確認） | `node scripts/ui-smoke.js` |
| 主要画面のスクリーンショット保存 | `node scripts/ui-smoke.js --shots <フォルダ>` |
| 2つの保存結果を比べる | `node scripts/ui-smoke.js --compare <変更前> <変更後>` |
| 変更前の状態を別フォルダに取り出して撮る | `git archive HEAD フォワーダー支援 \| tar -x -C <フォルダ>` のあと `node scripts/ui-smoke.js --root <フォルダ> --shots <before>` |

- 御見積書は長いため、文書だけを別の領域に描き出して全体を撮る（通常・発生時のみ／参考情報／概算の注記・FCL案/LCL案の併記・英語出力の3種）。
- スモークテストには Playwright と Chromium が必要。`NODE_PATH` に playwright の node_modules、`CHROMIUM_PATH` に Chromium を指定できる。
- スクリーンショットは固定の日付・サンプルデータ・固定サイズで撮るため、変更が無ければ何度撮っても差は 0。
  ただしフォント等が環境で違うと差が出るので、**変更前後は同じ環境で撮る**（基準画像はリポジトリに置かない）。
- `docs/ui-contract.json` は「壊してはいけないつなぎ目」の基準。意図して部品名を変えたときだけ
  `node scripts/check-ui-contract.js --update` で作り直す（その差分をレビューする）。

## 手順
1. **変更前**：`node scripts/ui-smoke.js --shots <before>` で現在の見た目を保存（同時に動作確認も通る）。
2. 別ブランチでデザインを変更する（原則 CSS のみ。HTML を触るときは id・class・data-*・onclick を残す）。
3. **変更後**：
   - `node scripts/check-ui-contract.js` … NG が出たら、そのつなぎ目を直す（または意図した変更なら基準を更新）。
   - `node scripts/ui-smoke.js --shots <after>` … 動作確認がすべて OK であること。
   - `node scripts/ui-smoke.js --compare <before> <after>` … 差のある画面が意図した範囲か、差分画像（`<after>/diff/`）で確認。
4. 問題が無ければ PR → マージ。問題があれば、そのブランチ／PR を取り消す。

## Industry テーマ（Claude Design 案）の切替と元に戻し方
Design から受け取った Industry 版（鋼青のブループリント調）は、**現行 CSS を一切書き換えず**、オン／オフで切り替えられる「着せ替えレイヤー」として載せてある。**既定は現行デザイン**。

| 項目 | 内容 |
|---|---|
| 切替の入口 | ヘッダー右上の「🎨 デザイン」→ 画面／御見積書をそれぞれ「現行｜Industry」で選ぶ（設定はこのブラウザの localStorage `forwarderTheme_v1`） |
| URL で一時切替 | `…/index.html?theme=industry`（画面＋御見積書とも Industry）／`?theme=classic`（現行に戻す）。値は保存される |
| 元に戻す（個人） | 上記パネルで「現行」を選ぶ。または `localStorage.removeItem('forwarderTheme_v1')` |
| 元に戻す（全員・恒久） | `index.html` の `theme-industry*` を読み込む 3 本の `<link>`＋早期スクリプトを削除（または `css/theme-industry*.css` を削除）。他のコードはテーマ未適用でも動く |
| 仕組み | `<html class="theme-industry">`（画面）／`theme-industry-doc`（御見積書）のときだけ、`css/theme-industry.css`／`theme-industry-doc.css` が効く。セレクタは `:where(html.theme-industry)` で包み、詳細度を増やさない |
| 生成 | `node scripts/build-industry-theme.js`（`docs/design-handoff/industry/css/` と現行 CSS の**差分だけ**を出力）。`--check` で最新か確認。生成物は手編集しない |
| 3階層（カテゴリ見出し） | Industry のときだけ `row.js` の `_insertCatHeaders()` が表示専用の仮想行 `tr.subcon-cat-header` を挟む（保存・出力には含まれない）。現行テーマでは何も挿入されない |
| 動作確認 | `node scripts/ui-smoke.js --theme both --shots <dir>`（現行は `--theme` なし。現行の見た目が変わっていないことは `--compare` で確認） |

注意：Industry の間は Tweaks の「アクセント」「基調」（配色）は無効（テーマ側の配色が優先）。「情報密度」は引き続き有効。
Industry では操作ボタンが行ホバー時のみ、`カテゴリ` 選択欄は行を編集中（focus-within）のみ表示される（Design 仕様）。

## かんたん表示（新規ユーザー向けの簡易表示）
Claude Design 案の「かんたん表示」を、**切替式・元に戻せる形**で導入している（`docs/design-handoff/simple-mode/` に引き渡し資料）。

| 項目 | 内容 |
|---|---|
| 仕組み | `<html class="mode-simple">` が付いていれば「かんたん」、無ければ従来の「詳細」。保存は localStorage `fwd.uiMode`。`?mode=simple|detail` でも切替（保存される）。切替UIはダッシュボードのタイトル行右（`.uim-switch`）。コードは `js/ui-mode.js`・`css/simple-mode.css` |
| 既定値 | `index.html` 先頭の `UI_MODE_DEFAULT`（**段階導入中は `'detail'`＝従来どおり**）。動作確認後に `'simple'` へ変えると、保存設定の無い全員が「かんたん」になり、初回だけ案内が出る（`fwd.uiHintSeen`） |
| 隠す項目 | `display:none` で DOM に残す（値の保存・計算は継続）。かんたん専用の要素は詳細表示では CSS で非表示 |
| ダッシュボード（実装済み） | 案件カード（見出し＝メモ1行目→ルート→REF#／「開く」＋「⋯」メニュー／申し送りは畳む）、リスト7列、「詳しく絞り込む」、ログイン前の2カード |
| 見積入力画面（実装済み） | 区分 `data-tier`（req＝常に表示／opt＝「詳細（任意）」に畳む／adv＝かんたんでは隠す）、必須／任意バッジ、手順の道しるべ（① 条件 → ② 貨物 → ③ 費用 → ④ 出力）、固定ツールバー整理（取り込み・サブコン依頼メール・表示の大きさは「⋯」へ）、右レール（ジャンプ／金額／申し送り＋「その他」）、作業範囲・全体リマークは畳む。**上級機能を使っている案件は、その項目を自動で表示し、帯で知らせる**（出発地／到着地ゾーン、複数の荷姿パターン、FCL/LCL比較、危険品・特殊貨物）。隠した欄も DOM に残り、保存・計算は継続 |
| 元に戻す | 個人：「詳細表示」を選ぶ／`?mode=detail`。全員・恒久：`UI_MODE_DEFAULT` を `'detail'` のまま、または `js/ui-mode.js`・`css/simple-mode.css` の読み込みを外す |
| 画像の生成 | ダッシュボード：`MODE=simple node scripts/sample-dashboard-shots.js`／見積入力：`node scripts/sample-editor-shots.js`（架空データ。`THEME=1` で Industry 適用、`W=390 H=844` でモバイル幅） |

詳細表示は従来と同じ見た目（切替スイッチの追加分のみ差）であることを、変更前後のスクリーンショット比較で確認済み。

## 既知の未実装（今回の変更とは無関係）
HTML から呼ばれているが JS に定義が無い関数：`quickLookup`（追跡）・`freetimeLookup`・`judgeIncoterms`・`resetIncoterms`。
基準ファイルには「未定義」として記録済みなので、デザイン変更の失敗としては数えない（`docs/バグ台帳.md` の既知の不具合）。
