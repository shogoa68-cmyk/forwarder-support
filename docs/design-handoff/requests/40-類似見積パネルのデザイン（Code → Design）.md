# 見積入力：右レール「🔍 類似見積」パネルのデザイン見直し（Code → Design）

2026-11-19。右レールの「類似」で開く引き出し（`#sqPanel`）を、**「探してから結果を見る」流れ**に作り替えたところ、機能は動くが見た目が粗い。デザインを整えてほしい。画像は `images/`、現在のコードは `source/`。

## 1. 何が変わったか（機能は実装済み）
以前は、見積の条件（モード・貿易条件・POL・POD・お客様）を入力するたびに、**類似の過去見積が自動で並んだ**（画像 `sample-40-before-results.png`）。いきなり提案が出るので邪魔だった。
いまは、**新規見積の入口の「似ている案件を参考に作成」と同じ動き**にした（画像 `sample-40-new-quote-entry-card.png`＝あの入口のカード）。

流れ：
1. 「類似」を開く → 上に「🔗 関連付けた案件」、その下に**入口カード「🔍 似ている案件を探す」だけ**を出す（以前の自動候補は出さない）。
2. カードを押す → **検索画面**に切り替わる（画像 `sample-40-current-search.png`）。いま開いている見積のお客様・POL・POD・輸送モードが最初から入る。
3. ［🔍 探す］（または入力欄で Enter）を押したときだけ検索。条件なしでも探せる（新しい順）。
4. 結果は類似度の高い順に 5 件ずつ。［もっと見る（あと N 件）］で追加。カードを押すとプレビュー（行の追加・航路のコピーができる）。
5. 右上の✕（検索画面）で入口カードに戻る。

## 2. 困っていること（現在の画像 `sample-40-current-search.png`）
- **入口カードが素っ気ない**。新規見積の入口のようなカード（アイコン・太字の題・説明）が出るが、検索画面に入ると消えて、画面が「入力欄が縦にずらっと並ぶだけ」に見える。
- 入力欄が **幅いっぱいの細い線の欄**で、ラベルが無くプレースホルダだけ。何の欄か、入力後に分からなくなる。
- 輸送モード・状態のチップ（すべて／FCL／LCL／AIR・すべて／提示済み／受注／失注）が**小さく（約 12px・高さ 18px）て押しにくい**。選択中が黒背景でほかと馴染まない。
- ［探す］ボタンが青で大きく、［条件をクリア］が白で似た大きさ。**主・副の差が弱い**。
- 結果が出る前の案内文（「条件を入れて『探す』を押してください…」）が小さい灰色の 1 行で、画面の大部分が空白。
- **結果カード**（画像 `sample-40-before-results.png` の下半分）：案件名・ステータス・類似度の●○○・見積番号・お客様・ルート・日付が詰まっていて、どれが大事か分かりにくい。「なぜ類似なのか（どの条件が一致したか）」が見えない。
- 「🔗 関連付けた案件」（上の欄）と検索画面が同じ見た目で並び、役割の違い（＝手動で結びつけた案件／探して見つける）が伝わらない。

## 3. 作ってほしいもの
### 3-1. 入口の状態（探す前）
- 新規見積の入口カード（`.nq-card`）と**同じ言葉遣いのカード**にする（アイコン・題・1 行説明・押せる見た目）。説明文はいま「過去の案件から、お客様・積み港・揚げ港・モードで探します。見つけた案件はプレビューで中身を確認でき、行を追加できます」。
- 「いまの見積の条件で探す」**ワンクリックの近道**を足す案（例：［この見積の条件で探す］）も、あれば提案してほしい（現状はカードを押すと条件が入った検索画面に進み、さらに［探す］を押す 2 手）。**実装しやすいのは、近道を足さず現状の 2 手のままにすること**。近道を足すなら、押したら検索画面を経ずに結果まで出す動き。
- 条件入力が一つも無い（新規で何も入れていない）見積のときの見え方。

### 3-2. 検索画面（探す前・探した後）
- 条件欄に**ラベル**（お客様／積み港 POL／揚げ港 POD／輸送モード／状態／見積番号・見積名）を付け、まとまりで見せる。使う頻度が高い「お客様・POL・POD・モード」を先に、「状態」「見積番号・見積名」は［さらに条件 ▾］の奥へ、でも良い（実装は表示の出し分けだけ）。
- チップは**押せる大きさ（高さ 32px 以上・スマホ 44px）**、選択中が分かりやすい色（Industry の主色）に。
- 主ボタン［🔍 探す］と副ボタン［条件をクリア］の主・副の差。
- 探す前の空の状態、探した後の件数表示（「N 件が見つかりました」「該当なし」）、検索中の表示。
- 戻る（✕）の見え方（入口カードへ戻る）。

### 3-3. 結果カード
- 1 件の**情報の優先順位**：案件名＞お客様・ルート（POL → POD）＞モード・貿易条件＞見積番号・ステータス・更新日。
- **類似度**（現在は●●○の 3 段階）と、**一致した条件**（例：お客様✓・POD✓・モード✓）を見せる案。データとして持っているのは「お客様／POL／POD／モード／貿易条件のどれが一致したか」（探す側の条件と比べて分かる）。一致した条件だけ色を付けるなど、**見て分かる**形を。
- カード全体が押せること（プレビューを開く）が分かる見た目（ホバー／フォーカス）。
- ［もっと見る（あと N 件）］の見た目。

### 3-4. 「関連付けた案件」との区別
- 引き出しの上半分「🔗 関連付けた案件」（手動で結んだ案件。メイン／サブのツリー・理由・［＋ 関連付け］）と、下半分「🔍 似ている案件を探す」（検索）の**見出し・区切り**。2 つが 1 枚の同じ見た目で続いて見える。区切りと見出しで役割を分けてほしい。

## 4. 制約（これまでと同じ）
- 機能は消さない。**DOM・id・onclick・関数名は変えない**（表示の出し分け・クラス・CSS・並べ替えの追加は可。HTML の文字列は `similar-quotes.js` の `_sqIntroHtml`／`_sqSearchHtml`／`_sqCardHtml` で作っている）。
- 3 テーマ（現行／Industry（既定）／Quiet）で崩れないこと。文字は 12／13／14／16／18px の 5 段（`--text-xs/sm/base/lg/xl`）。タップ 44px（スマホ・指で触る端末）。
- 右レールの引き出しは幅 **340px が既定**（左端をドラッグして 300〜560px）。**狭い幅でも 1 列で読める**こと。
- 保存データは増やさない。検索はいまの案件一覧（Supabase）に対する問い合わせで、変えない。
- 見積入力の新画面（PC）と旧画面の両方で使う。スマホ幅（〜600px）は引き出しが下から出るシートになる。
