# Design への依頼：「新規ユーザーにも分かりやすい」画面への整理（見積入力画面・ダッシュボード）

## 1. 目的
多機能になった結果、画面の情報が多く、初めて使う人が迷う。**機能は減らさず**、新規ユーザーでも「何をすればよいか」が分かる画面にしたい。

**想定する新規ユーザー**：フォワーディング業務の知識はあるが、IT・Web アプリの操作に不慣れな人。
- 業務用語（インコタームズ、POL/POD、仕入/売値など）は分かる。
- 次は分かりにくい：アイコンだけのボタン、「ブラウザ保存」「プリセット」「パターン」「ゾーン」といったアプリ内の言葉、保存先がどこか、どこまで入力すれば完成か。

## 2. 守ってほしい条件（機能を壊さないため）
- **消さずに、隠す／畳む／並べ替える**。機能そのものの廃止・統合はこの依頼の対象外（別途、実運用を見て判断する）。
- `id`・`onclick`・`data-*`・JS が付け外しする class は残す（従来どおり。`docs/design-system/` の約束と同じ）。
- 隠した欄も DOM には残す（入力値の保存・計算が隠した欄を読むため）。**必須項目は隠さない**。
- 御見積書（A4 の出力）は今回の対象外。
- デザインの基調は **Industry 版**（切替式テーマとして導入済み、`docs/design-handoff/industry/`）を前提にしてほしい。

## 3. 依頼の中身（2画面）
### A. 見積入力画面（最優先）
サンプル画像：`sample-quote-screen-empty.png`（新規・空の状態）。

**現状（初回表示で実測）**：セクション7つ／入力欄74／ボタン124／縦約4,300px。最初の「管理番号入力」だけで縦約950px・入力欄12・ボタン19（見積そのものの入力に入る前に、管理用の項目が大半を占める）。上部に10個のタブ、固定ツールバー約10項目、右にアイコン10個のレール、右下に大きな3ボタン。

**分類（案）**
| 区分 | 項目 | 見せ方 |
|---|---|---|
| 必須 | 見積番号、お客様名・担当者、方向／インコタームズ／輸送モード、航路（港）、貨物の基本情報、費用の明細、合計、出力（PDF・プレビュー・保存） | 常に表示。上から順に埋めれば完成する流れ |
| ときどき | 日付類、ステータス、タグ、メモ、参照URL、添付、基幹REF#、関税・HS、物量パターン、全体リマークの個別プリセット | 見出しだけ出して畳む（「詳細（任意）」） |
| 上級者向け | FCL/LCL比較、複数航路、往復の復路設定、サブコンのグループ操作、行パターンの編集、選択モードの一括操作、右レールの各ツール | 「詳細表示」に切り替えた人だけに出す |

**依頼してほしいこと**
1. 「かんたん表示」と「詳細表示」の2状態の画面案（既定は「かんたん」）。切替スイッチの置き場所と見せ方。
2. 最初の1画面の整理：「管理番号入力」を必須3項目（見積番号・お客様名・担当者）に絞り、残りを畳む案。
3. 手順の道しるべ：「① 条件 → ② 貨物 → ③ 費用 → ④ 出力」と、いまどこで、次は何をするか（既存の進捗バー `qp-*` を活かしてよい）。
4. 固定ツールバー・右レール・右下ボタンの整理：アイコンだけのボタンには文字を添える。普段使わないものは「⋯」のメニューへ。
5. 必須／任意の区別の表現（印、色、文言）。

### B. 見積ダッシュボード
**現状（ログイン後・実運用データで確認）**：
- 上から：ステータスのタイル8個（全体／下書き中・改定中・情報待ち／提示済み／ヨコヨコ提示／受注／失注／辞退／保留。クリックで絞り込み）→ 長い検索ボックス → 操作の列（詳細検索、並び替え、カード／リスト、関連付けモード）→ タグ検索＋タグチップ（十数個＋「もっと見る」）→ 案件カードの一覧。右に「お客様別／タグ別」ランキング。
- 1枚の案件カードに、状態・案件番号・コピー・経過日数・料金フォロー・案件名・進捗（5段）・ルート・条件・サブコン・お客様/担当・作成/更新・タグ・更新日時・操作ボタン5個（プレビュー／PDF／読込／コピー／削除✕）・関連案件・申し送り（チャット欄）が入っている。

**気づいた課題**
- カード内で最も目立つのが「お客様名」で、案件名や次にやる操作より大きい。
- 開く操作（「読込」）が、プレビュー・PDF・コピー・削除（✕）と同じ並びで、削除が隣にあり誤操作しやすい。「読込」という言葉も分かりにくい。
- 進捗の5段（条件／貨物／仕入／利益／出力）は表示専用（クリック不可）だが、ボタンのように見える。
- 「申し送り」欄がカードごとに横幅の約3分の1を占める。空のカードが大半（「まだ申し送りはありません」）。
- タグチップや詳細検索、関連付けモードなど、上級者向けの操作が最初から全部見えている。
- 初回（ログイン前）の画面：「ログインせず新規作成（このブラウザ内のみ）」が小さなリンクで、意味（保存先が自分のPCだけで共有されない）が伝わりにくい。「編集画面へ」も何を編集するのか分からない。

**分類（案）**
| 区分 | 項目 |
|---|---|
| 必須 | 新規見積を作成／案件の一覧（案件名・状態・お客様・ルート・更新日）／検索／ステータス絞り込み／**開く** |
| ときどき | 並び替え、カード／リスト、進捗、担当・作成更新者、申し送り（件数だけ見せ、開けば入力欄）、プレビュー・PDF・コピー、お客様別ランキング |
| 上級 | 詳細検索、タグ絞り込み＋チップ、関連付けモード・関連案件、タグ別ランキング、削除 |

**依頼してほしいこと**
1. 案件カードの情報の優先順位づけ（何を大きく・何を小さく・何を隠すか）。「開く」を主役にし、プレビュー・PDF・コピー・削除は「⋯」メニューへ。
2. 申し送りは既定で畳み、件数バッジだけ見せる。
3. 上級者向け機能を「詳細」にまとめる案。
4. 初回画面（ログイン前）の整理：ログインの意味と、ログインしない場合の違いを、平易な言葉で。

## 5. 成果物の形式（前回の Industry と同じ）
- 変更する CSS（新規ファイルで可）と、変更の意図を書いた仕様書。
- **HTML・JS の変更が必要な箇所は、CSS だけでは実現できない旨と、必要な構造（例：行・要素の追加、`<details>` 化、クラスの付け外し）を明記**。それ以外は CSS のみで完結する案を優先。
- 「かんたん／詳細」の切替は、`<html>` や対象要素に付けるクラス名（例 `mode-simple`）と、各項目の区分（必須／ときどき／上級）を一覧で。

## 6. こちら（code）の担当
切替の仕組み（状態の保存、既定値、必須項目が隠れないこと）の実装、文言の置き換え、「⋯」メニューの動作、検証（既存の主要操作が「かんたん表示」でも通ること）。
