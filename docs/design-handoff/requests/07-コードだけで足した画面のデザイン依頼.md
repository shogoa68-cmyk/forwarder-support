# Design への依頼：コードだけで足した画面・部品の見た目の整理（07）

別のセッションで、機能の追加・レビュー対応を**コードだけで**進めたため、Design の案を通っていない画面・部品があります。
「Industry」の言語（鋼青・ブループリント調、同寸法の入力欄、枠の意味の使い分け）に合わせて、整理した案がほしいです。
画像は同梱（`images/`、**すべて架空データ**。Industry = `-industry`、現行デザイン = 付き無し）。再生成：`OUT=<dir> THEME=1 node scripts/sample-new-screens-shots.js`。

## 守ってほしい条件（これまでと同じ）
- `id`・`onclick`・`data-*`・JS が付け外しする class は残す。機能の廃止はしない（表示の整理のみ）。
- 隠した項目も DOM に残す（保存・計算は継続）。
- 詳細表示／かんたん表示、タッチ端末（ホバー無し）、スマホ幅で成り立つこと。
- **CSS だけで足りるものは CSS で、HTML／JS が必要なものは「必要な構造」を明記**（要素の移動・追加の一覧つき）。
- 客先向けの出力（御見積書・メール・プレビュー）は、今回は対象外（ただし文言を変える提案は、候補として挙げてください）。
- 見積テーブルの行レイアウト（v3：3段固定・「その他 ▾」パネル）は取り込み済み。その上に重ねる形で。

## A. 見積テーブル（見積入力画面）
**画像：`n1-table-industry.png`（全体）、`n2-min-panel-industry.png`（ミニマムの欄）、`n1-table.png`（現行）**

### A-1. 「（パターン設定なし）」のまとまり
- 現状：パターン欄が空の行も、サブコンの下の「🔖（パターン設定なし）」のまとまりに入る（サブコン → パターン → カテゴリ → 明細のツリーをそろえるため）。見出し・小計・折りたたみ・除外・並べ替えは、名前付きのパターンと同じ。見出しは「控えめな色」にしてある。
- 構造：`tr.subcon-subgroup-header.is-pt-unset`（見出し）、小計は「そのサブコンに名前付きのパターンもあるときだけ」。行の「パターン」欄は空のまま（表示だけの仮の見出し）。
- 見てほしい点：
  1. 名前付き（例「FCL案」）と設定なしの**見分け**。いまは淡い色の違いだけ。
  2. サブコン（黒帯）→ パターン（水色帯）→ カテゴリ（灰帯）→ 明細の **4 段の見出しが続いて重い**。特に、パターンが 1 つだけ・設定なしだけのサブコンでも 3 段の見出しが並ぶ。省略・統合の案（例：設定なしだけなら見出しを出さない、カテゴリ見出しをパターン見出しに寄せる）があれば。
  3. 小計行の情報量（仕入合計・売値合計・粗利率・客先表示名・＋行追加・サブコン別リマーク）の整理。

### A-2. ミニマム（最低料金：「Min. $28.00 or $0.15/kg」）
- 現状：フラグ群に「MIN」ボタン。ON にすると、Industry は「その他 ▾」の中に **MIN 仕／売** の入力欄（`.min-group`／`input.w-min` の `ppmin`・`bpmin`）が出る。現行デザインは行の中。最低料金が適用されると、行の小計セルの 3 段目に状態チップ「MIN 適用」（`.state-chip`）が出る。金額は「数量 × 単価」と最低料金の高いほう。
- 構造：`button.min-mode-btn`（`.is-on`）、`tr.row-min-mode`、`tr[data-min-applied="1"]`。
- 見てほしい点：
  1. MIN の入力欄の**見た目と位置**（ラベル「MIN」「仕」「売」の置き方、他のフラグ・単価欄との関係）。
  2. 「MIN 適用」チップと、行の単価欄の関係。**単価欄は 0.1 のままで、金額だけが最低料金（28）になる**ため、画面上は「0.1 × 100 ≠ 28」に見える。適用中であることを、行の単価まわりで分かりやすく示す案（例：単価の下に「Min. 28.00」の小さな表示）。
  3. 現在の MIN の「ON」状態（ボタンが ON でも、最低料金が空なら何も起きない）の示し方。

### A-3. 名前の入力欄の「未登録」の印
- 現状：品名・港・お客様・キャリア・サブコンの入力欄で、入力候補（マスター）にない名前には、**橙色の点線の枠**（`input.name-unregistered`）と説明（`title`）が付く。吹き出しは出さない。
- 課題：Industry では、**点線の枠は「表示専用（入力できない）」の意味**（売値の欄など）に使っている。同じ点線が「未登録の警告」にも使われ、**意味が衝突**している。また、画像のように、マスターが整っていない間は多くの行が点線になり、うるさい。
- 依頼：「枠の言語」の整理案。入力可（実線）／表示専用（点線・灰地）／警告・注意（未登録など）を、色・線・アイコンでどう使い分けるか。未登録の印は、枠ではなく小さなマーク（例：名前の右端の点やラベル）にする案も含めて。

### A-4. 用語の説明（業務略語）と単価の見出し
**画像：`n3-glossary-industry.png`**
- 現状：テーブルの見出し行に「📖 用語の説明」ボタン（`#quoteGlossary` の用語集を開く）。単価の見出しは「仕入＋乗せ幅＝売値」（CD の説明も追加）。外貨を含むとき、合計行に「※ 外貨の金額は、換算レートで円にして合算しています」（`#tot-fx-note`）。
- 課題：用語集（POL/POD、FCL/LCL、R/T、C/W、BAF/CAF…）が、**画面の上に文字だけで長く並ぶ**（約 30 行。段落の区別がない）。
- 依頼：用語集の見せ方（開く場所：モーダル／右レール／ポップオーバー、グループ分け：数量・運賃・書類・サーチャージ、検索）。「※」の説明の置き場所・大きさ。

## B. マスター管理タブ（承認制・クラウド必須）
**画像：`n4-master-admin-industry.png`（管理者）、`n5-master-member-industry.png`（メンバー）、`n4-master-admin.png`（現行）**
- 現状：マスター管理タブは、Industry の見た目がほとんど当たっていない（現行デザインとほぼ同じ見た目）。以下が縦に並ぶ：
  1. 移行の案内（`.master-cloud-notice.is-migrate`）：このブラウザにだけあるデータを数えて、「☁️ チームへ移す」「移さない」（件数と例を表示）。
  2. マスターの申請（`.stats-req-section`）：管理者は承認待ちの一覧と「承認」「却下」、メンバーは「あなたの申請」（承認待ち／承認済み／却下、取り消し）。
  3. 「➕ 代表を新規登録」のフォーム、種別の絞り込みチップ、活用方法の説明、個別マスターの表、同義グループの表（別名の追加・統合・名称変更・解除・詳細）。
- 課題：
  1. **役割（管理者／メンバー）で画面が変わる**のに、ひと目で分からない。承認待ちの件数（管理者の最優先の作業）が目立たない。
  2. 移行の案内は一度きりの重要な操作なのに、黄色い帯が文章で長い。「移す」「移さない」の重みの違い（後者は元に戻せない）が見えない。
  3. 表が 2 種類（個別マスター／同義グループ）あり、列・操作ボタンの並びが異なる。操作ボタンが小さい（統合・名称変更・解除・詳細・＋別名）。
  4. 左下の浮きボタン「← 見積もりに戻る」（`#backToQuoteFab`）が、表の内容に重なる。
- 依頼：マスター管理タブ全体の Industry 版。申請・承認の流れ（メンバー：申請 → 承認待ち → 承認済み／却下、管理者：承認待ちの一覧 → 承認／却下）を、かんたんに分かる形で。状態は文字＋形（色だけに頼らない）。承認／却下／解除など**取り消しにくい操作**は、確認の見せ方も含めて。

## C. スマホ幅（390px）の見積入力画面
**画像：`n6-mobile-industry.png`**
- 現状：上段のカテゴリタブは 1 段の横スクロール（以前は 4 段で入力欄を隠していた）。ツールバー（ダッシュボードに戻る／元に戻す／メール取込／サブコン依頼メール／ブラウザ保存／文字サイズ／かんたん・詳細）は 3 段に折り返す。右下のドック（PDF出力・プレビュー・保存）は、小さくして、ページ下に余白を確保。
- 課題：ツールバーが 3 段で、入力を始めるまでの距離が長い。ドックが入力欄に重なる。表（明細）は横スクロール。
- 依頼：スマホ幅での、上部（ヘッダー・タブ・ツールバー）と、ドックの整理案。明細テーブルのスマホ表示（カード型など）は、**行レイアウト v3 を前提に**、可能なら別案として。
