2026-11-19。Design 40（入力欄の 2 列の格子）・41（プレビューと PDF 出力の役割分け）は実装済みです。あわせて、Code だけで進められるものは片づけました（下の 0）。**残りは見せ方を決めないと進められないものだけ**なので、まとめて相談します。画像は `sample-42-*.png`（新画面・Industry）。

- 41：A〜I すべて。表計算のサブコン小計は、**仕入合計を「仕入」の列、粗利率を「利益」の列**へ移しました（仕入の列を隠したときだけ「↳ 小計」の横に戻る）。御見積書のサブコン名は、客先表示名を入れたときだけ出します。

## 1. プレビュー（表計算）が横に収まらない（`sample-42-preview-wide.png`）
- 列が 17 あり、1440px の画面でも右端（「利益」の一部・「備考」）が横スクロールの先に出ます。見出しを 2 段（項目｜仕入｜請求｜結果）にしたので、まとまりは分かるようになりました。
- 案：
  - **a**：左の 3 列（カテゴリ・サブコン・項目名）を固定して、残りを横スクロール
  - **b**：既定で出す列を減らす（CD・円換算・消費税は既定でオフ。左の［表示列］で出せる）
  - **c**：1 明細を 2 段にする（上段＝仕入、下段＝請求）
- Code の見立て：b がいちばん安全（表の作りを変えない）。a はスクロールの影の付け方などの見た目を決めてほしい。

## 2. プレビューのスマホの上部（`sample-42-preview-phone.png`）
- 上部のボタン（メール本文・Excel・印刷 横／縦・PDF 出力・閉じる・⚙ 設定）が 3 段に折り返し、表が下へ押し出されます。
- 案：1 行に［⚙ 設定］［⋯］［PDF 出力（主）］［閉じる］。メール本文・Excel・印刷は［⋯］の中へ。
- 確認したいこと：スマホでは印刷（横／縦）を出さなくてよいか。

## 3. 幹線輸送の「航路」の一覧（`sample-42-route-list.png`）
- 登録した航路 1 本が 1 行で、小さなボタンが最大 10 個並びます（並べ替え ↑↓・使う ✓・案の名前・採用／不採用・区間・キャリア・航路・使用不可 🚫・✎・✕）。
- 上の POL／POD の入力欄は「次の航路を足すための欄」で、登録済みの航路はその下の一覧です。画像のように、入力欄が空のまま一覧に 3 本ある状態では、どちらを見ればよいか分かりにくいと Code は見ています。
- データは次のものを持てるようになりました（どれも見積書の出力・合計には影響しない「控え」）：
  - **案の名前**（例：案1 直行）
  - **採用／不採用**
  - **区間**（集荷／海上／配送などの区間ごとに、業者・ETD・メモ）
- 決めてほしいこと：
  1. 航路の一覧の形（いまの 1 行のままか、1 航路＝1 枚のカード〈案の名前を見出し・区間を縦の流れ・操作は［⋯］へ〉か）
  2. 入力欄と一覧の関係（入力欄を「＋ 航路を追加」の奥に畳むか、など）
  3. 採用した案だけを御見積書に出すようにするか（いまは「使う ✓」が出力を決め、採用の印は控えのみ）

## 4. マスター管理のスマホの残り（`sample-42-master-phone-list.png`・`sample-42-master-phone-more.png`）
- スマホ向けの組み替えをまだしていない画面が 2 つあります（PC の作りのまま縮んで出ます）：
  - **新規登録のモーダル**
  - **エイリアス是正**（古い表記を一括で置き換える画面）
- 決めてほしいこと：
  1. 新規登録をスマホで下から出るシートにするか（種別 → 名前 → 詳細の順に 1 列）
  2. エイリアス是正をスマホで使えるようにするか（PC だけでよいか）
  3. 「マスターから解除」の確認に、その名前を使っている案件の件数を出すか
  4. 先のお客様（入れ子）の見せ方（いまは「🔗 先のお客様 N社を見る ›」で開閉）
- ついでに見つけたこと：画面の上と下に通知（トースト）が 2 か所から出て、❓ の吹き出しとも重なる場面があります（画像の上と下）。スマホでは通知の場所を 1 か所にそろえたい。場所の指定をください。

## 5. 統計のスマホの残り
- 受注分析は数字のカードだけで、横棒グラフがありません（PC は横棒あり）。
- KPI（準備中）の画面の見せ方が決まっていません。
- 「☆ 登録」と「☆ マスターに登録」（PC では別の操作）を、スマホで 1 つのボタンにしてよいか。

## 6. 見積入力の「旧い画面」の扱い
- 新しい画面が既定になりました（☰ の「画面の切替」で旧い画面にも戻せます）。
- 旧い画面を残すと、同じ機能を 2 通りの見た目で保つことになり、直すたびに両方の確認が要ります。
- 決めてほしいこと：旧い画面を残す期間と、☰ の切替をいつ外すか（廃止するなら、その前にお知らせを出す文面）。

## 7. サブ案件の廃止後の表示
- 新しく作る入口は隠しましたが、**すでにあるメイン／サブの表示**（カードの入れ子・「↳ サブ：○○」・番号の (A)(B)）は残っています。
- 新しく作れないのに表示だけ残ると戸惑うかもしれません。見せ方を決めてください：
  - **i**：そのまま
  - **ii**：「関連」の 1 種類として表示（入れ子をやめて、カードに「🔗 関連 N件」だけ）
  - **iii**：「旧サブ案件」の札を付ける

## 8. 制約（いつもどおり）
- 既存の DOM・id・onclick・保存データは変えない（見た目の出し分け・要素の移動だけ）。
- 3 テーマ（Industry／現行／Quiet）で崩れないこと。文字は 12／13／14／16／18px。スマホはタップ 44px 以上。
- 3 の「採用した案だけを出力」は、お客様に渡る書類が変わるので、決めてもらってから入れます。
