# 顧客カルテ（お客様ごとの事例の記録）の画面の整理（Code → Design）

2026-11-19。見積入力の「📌 取引ルール」の帯にある［🗂 過去の事例］から開く画面と、マスター管理のお客様の詳細のタブ「顧客カルテ」の中身です（中身は同じ部品）。画像は `sample-44-*.png`（`-empty-user` はユーザーの実画面＝事例 0 件・入力途中。ほかは偽のデータで 3 件ある状態・1440px と 390px・Industry）。

## 0. いまの作り（前提）
- 1 件の事例＝発生日・分類（⏱️遅延／📄書類／💴費用・請求／📦貨物・事故／📞連絡・手配／📌その他）・見出し・**何が起きた／どう解決した／次回どうすれば良いか**・案件の管理番号・関係したサブコン・先方の担当者・状態（未解決／解決済み）・登録者。
- 事例ごとに［編集］［解決済みにする／未解決に戻す］［📌 ルールにする］（「次回どうすれば良いか」を取引ルール＝要確認として登録）［削除］。
- 社内専用（御見積書・メール・プレビューには出ない）。チームで共有。

## 1. 問題
1. **一覧と追加の入力欄が 1 つの画面に縦に並び続ける**（`sample-44-cases-pc.png`）。事例が増えるほど入力欄は下へ押し出され、記録したいときにスクロールが要る。逆に 0 件のとき（`-empty-user`）は入力欄がいきなり全部出ていて、何から書けばよいか迷う。
2. **入力欄に見出しが無い**：「見出し」「何が起きたか」「どう解決したか」「次回どうすれば良いか」は例文（placeholder）だけで、書き始めると何の欄か分からなくなる。必須（見出し）と任意の区別も無い。
3. **入力欄の大きさがそろっていない**：日付・分類・管理番号の高さ・幅がまちまち、文章の欄は 2 行で狭い、［＋ 事例を追加］が小さく目立たない。
4. **事例ごとのボタン 4 つが同じ強さで縦に並ぶ**（PC）。［削除］が［編集］と同じ見た目で隣にある。
5. **未解決と解決済みの見分け**：左の線の色（赤／緑）と札だけ。未解決を先に見たい、解決済みは畳みたい、という使い方に対応していない。
6. **「📌 ルールにする」が何をするのか分かりにくい**（取引ルールとの関係・ルール化済みの印）。
7. **スマホ**（`sample-44-cases-phone.png`）：1 件が縦に長く、追加の入力欄は画面のずっと下。
8. 上の説明文（「このお客様の過去の事例…」）と、0 件のときの説明、下の「🔒 社内専用です…」の 3 つが同じようなことを繰り返している。

## 2. 案（Code の考え）
- **A：一覧が主・追加は［＋ 事例を記録］で開く**：画面は一覧だけ（未解決が先・解決済みは「解決済み N 件 ▾」で畳む）。［＋ 事例を記録］で入力欄（またはその場の小さな画面）が開く。編集も同じ入力欄。
- **B：左に一覧・右に詳細／入力**（PC）：選んだ事例の全文と操作を右に。スマホは一覧→詳細の切替。
- **C：今のまま並べ替えだけ**：入力欄を一覧の上に移し、畳んだ状態（「＋ 事例を記録」の 1 行）から始める。
- Code のおすすめは **A**（いちばん変更が少なく、0 件のときも迷わない）。

## 3. 決めてほしいこと
1. A／B／C のどれにするか。
2. 入力欄の並びと見出し（必須は見出しだけでよいか／3 つの文章欄の高さ）。
3. 事例ごとの操作の置き方（［編集］だけ出して、ほかは［⋯］へ、など）。削除の位置。
4. 未解決・解決済みの見せ方（並び順・畳む・絞り込み）。
5. 「📌 ルールにする」の名前と説明（例：「取引ルールに登録」）。ルール化済みの印。
6. 説明文を 1 か所にまとめる文言。
7. スマホの組み方（入力は下から出るシートか、など）。
8. マスター管理の詳細（タブ「顧客カルテ」）も同じ見せ方でよいか（中身は同じ部品）。

## 4. 制約（いつもどおり）
- 保存データ（`customer_cases` の列）は変えない。項目を増やす案がある場合は別に相談。
- 3 テーマ（Industry／現行／Quiet）で崩れないこと。文字は 12／13／14／16／18px。スマホはタップ 44px 以上。
- 取り消しにくい操作（削除）の確認は `uiConfirm`（今どおり）。
