## 1. ごちゃごちゃに見える原因（Code の見立て）
1. **定型文のボタンが 15 個、同じ強さで 2 段（スマホは 7 段）**。文章の欄が画面の下へ押し出され、スマホでは欄が見えるまでスクロールが要る。どれが入っているかは点灯でしか分からない。
2. タブの「0」の件数（チーム人気 0・チーム共有 0・個人 0）が並び、使っていないタブも常に見える。
3. **補助の欄が 3 つ縦に並ぶ**（品物別リマーク・常時付記・画像を添付）。それぞれ違う見た目（選択欄／点線の枠／小さなボタン）で、「?」も 3 つ。常時付記の説明文が長い。
4. 「全体リマーク・免責事項」の見出しに札と「?」が付き、本文の見出し「5 リマーク・出力」とも重なる。
5. **出力のボタンが 3 か所**（上のバー・出力するの枠・スマホの下の固定）。⑤の中で同じボタンが 2 回見える。［次へ］が押せないまま残っている。
6. 「出力する」の枠が、リマークの補助の欄のずっと下（PC では画面の外）。
7. **スマホ**：画面が横に少しはみ出している（ページ全体の幅が 390px を超えて約 423px）。タブが 2 段に折れ、見出しの札と「?」が重なる。ステップの名前が切れる（「リマーク・出」）。

## 2. 案（Code の考え・参考）
- **A：文章の欄を主役に**：見出しの直下に文章の欄。定型文は欄の上の［＋ 定型文を入れる ▾］（押すと分類のタブとボタンの一覧が出るパネル・入っている定型文は欄の下にチップで表示し ✕ で外す）。品物別・常時付記・画像は［その他の付記 ▾］（件数つき・入っていれば開く）にまとめる。出力は最後に 1 つの枠（上のバーのボタンと役割が重ならない見せ方に）。
- **B：今の並びのまま、定型文のボタンを小さく・よく使う 6 つ＋「すべて ▾」にし、補助の欄の見た目をそろえる**。
- Code のおすすめは **A**（①〜③の「要約＋その場で開く」とそろう・スマホで欄が最初から見える）。

## 3. 決めてほしいこと
1. A／B（または別案）。①〜③（依頼 46・47）とそろえるか。
2. 定型文の選び方（ボタンの並べ方・タブ・件数 0 のタブの扱い・入っている定型文の見せ方）。
3. 文章の欄の高さ（最初の行数・伸びるか）と、文字数・クリアの位置。
4. 品物別リマーク・常時付記・画像を添付のまとめ方と説明文。
5. 見出しの札「📄 見積書に載ります」と「?」の置き場所。
6. 出力のボタンの見せ方（上のバーとの重なり・⑤の［次へ］の扱い・「出力する」の枠の位置）。
7. スマホの組み方（横にはみ出す件・タブの折り返し・欄が最初から見えるか）。

## 4. 制約（いつもどおり）
- 保存データ・id・onclick は変えない（表示の出し分けと要素の移動だけ）。旧画面（下の引き出し）はそのまま。
- 定型文のボタンは `ui.js renderRemarkPresets` が作る（点灯の仕組みはそのまま使う）。チーム共有・個人の定型文はログイン中だけ。
- 3 テーマ（Industry／現行／Quiet）で崩れないこと。文字は 12／13／14／16／18px。欄の高さは PC 36px／スマホ 44px（Design 40）。スマホはタップ 44px 以上。
