## 1. ごちゃごちゃに見える原因（Code の見立て）
1. **同じ情報が 3 か所**：案件番号・案件名は上のバー／左のステップの要約／本文の見出し、ステータスは上のバーの札と本文のボタン。
2. **札・小さなボタンが多い**：「自動」「標準」「?」「📇 詳細」「📝 社内メモ 🔒 社内だけ」「変更」「変更 ▾」。どれも強さが同じで、目が止まる場所が多い。
3. **点線の［＋ 〜を追加］が 3 本**（関連番号・提出期限・その他の情報の帯）と小見出し 3 つ（まず入れるもの／日付／必要なときだけ開く）。区切りが細かい。
4. **「その他の情報」の帯の文字が長い**（中身の列挙＋要約＋「入力欄を開く」）。開くと依頼受信日が見積もり番号の右の空きへ入り、並びが変わる。
5. ラベルが長い（「お客様 ご担当者（敬称略）」）。
6. Industry の枠（四隅の印・薄い青の箱）の中にさらに枠（点線の帯）がある。
7. スマホ：ステータスのボタン・社内メモのボタンで縦に長く、［変更］が ❓ ボタンに重なる。ステップの名前が切れる（「リマーク・出」）。

## 2. 案（Code の考え・参考）
- **A：必須 4 つだけの「カード」＋ 下に 1 行ずつの要約**：お客様・ご担当者・案件名・見積もり番号だけ常時。日付・関連番号・タグなどは「発行 11/19・有効 11/30・受信 11/19」のような 1 行の要約で、押すとその場で開く。ステータスは上のバーの札だけ（本文から外す）。
- **B：2 カラム（左＝入力・右＝この案件の状況）**：右にステータス・日付・取引ルール・ファイルをまとめた細い列。
- **C：今の並びのまま、札と小見出しを減らすだけ**（自動／標準の札を文字色に、「?」を欄名の吹き出しへ、小見出しを 1 つに）。
- Code のおすすめは **A**（必須が一目で分かり、他のステップの「要約の帯」とも同じ考え方）。

## 3. 決めてほしいこと
1. A／B／C（または別案）のどれにするか。
2. 本文のステータスのボタンを残すか（上のバーの札から変えられれば十分か）。
3. 「自動」「標準」の札、「?」、［📇 詳細］［📝 社内メモ］の見せ方・置き場所。
4. 日付・依頼受信日・関連番号・提出期限・タグ・REF#・参照資料の畳み方と、要約の文言。
5. 取引ルールの帯（ログイン中・お客様を選んだとき）の位置。
6. 作業範囲をどのステップに置くか。
7. 本文の見出し・左のステップの要約・上のバーの重複をどう減らすか。
8. スマホの組み方（❓ との重なり・ステップの名前の切れ）。
