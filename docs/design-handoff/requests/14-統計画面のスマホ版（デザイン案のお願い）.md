# 統計画面のスマホ版 — デザイン案のお願い（Code → Design）

2026-11-12。上段タブ「📊 統計」（`#tab-stats`）の**スマホ版**を作りたいので、**いくつか案**を出してもらい、選んだ案をコードに落とします。今の画面と制約をまとめます。画像：`stats-mobile-current.png`（390px 幅・データ 0 件の状態）。

## 1. これは何の画面か
- 見積案件（チーム共有）と明細を集計して、**名前のゆらぎを直す・マスターに登録する・受注や粗利を分析する**ための画面。主な使い手は管理者と見積担当。
- PC では上部のツールバー（期間・集計・使い方）、数字カード 6 枚、タブ 14 個、タブごとの表・グラフ、の構成。
- 同じ画面の中に、隣のタブ「🗂 マスター管理」（別画面・カード表示済み）がある。

## 2. 今の構成（PC・上から）
| 区画 | 中身 |
|---|---|
| ツールバー | 期間（全期間／今年度／直近3ヶ月／今月）・🔄集計・クラウド状態の札・「? 使い方」 |
| 数字カード 6 枚 | プリセット数／明細行数／SV・キャリア種類／品名グループ数／ゆらぎグループ／マスター候補数 |
| タブ 14 個 | **集計・分析**（下表） |
| タブの中身 | タブごとに表・並び替え・絞り込み・ボタン（☆登録・→別名・「ゆらぎ」バッジなど） |

### タブ 14 個（2 系統に分けられると思っています）
| 系統 | タブ | 見るもの |
|---|---|---|
| 名寄せ・マスター | 🏢 サブコン／🚢 キャリア／👤 お客様／📝 品名／📐 単位／💰 チャージ | 入力された表記ごとの使用件数・ゆらぎ・マスター登録／別名にするボタン |
| 分析 | 🔗 サブコン×港／🧾 お客様×品名／📒 明細台帳／🎯 マージンばらつき／🎲 受注分析／🔖 パターン別 | 組み合わせの実績・明細の一覧・粗利のばらつき・受注率（粗利率帯／お客様別／経路別／回答スピード別／失注理由）・パターン別の粗利 |
| 指標 | 📊 データ／🎯 KPI | 総案件・受注数・失注数・受注率・見積作成者別成績（KPI は準備中） |

## 3. 今のスマホ（390px）で困っていること
- タブ 14 個が折り返して **5 段**になり、本題の表まで画面 1 枚分以上スクロールしないと着かない。
- 数字カードが 2 列 × 3 段で、縦を大きく使う。
- 表が多く、**横に長い**（特に 明細台帳・マージンばらつき・受注分析・サブコン×港）。スマホでは横スクロールか文字が潰れる。
- 画面下の固定ボタン「← 見積もりに戻る」が一覧の最後の行に重なる。
- 1 行ごとにボタンが複数（☆登録／→別名にする／詳細など）あり、指で押し分けにくい。

## 4. お願いしたいこと
**3 案くらい**、方向の違う案を見せてください（紙芝居でも HTML でも可）。

- **案の観点（例）**
  - タブの出し方：選択式（プルダウン／ボトムシート）・2 段（系統 → タブ）・横スクロールのチップ、など
  - 数字カード：1 行の横スクロール帯／折りたたみ／最重要の 2〜3 枚だけ出す、など
  - 表の見せ方：1 行＝1 カード／主要な 3〜4 列だけ出して「詳細 ▾」で残りを開く／ドリルダウン（一覧 → 詳細の 2 画面）、など
  - よく使うもの（受注分析・KPI・名寄せのゆらぎ）への最短の入口の作り方
- **まず優先して見たい画面**：①サブコン／お客様などの名寄せ（ゆらぎ・マスター登録）②受注分析③明細台帳（← ユーザーに確認中。決まり次第お知らせします）
- 各案の**良い点・割り切り**も一言ください（選ぶ材料にします）。

## 5. 守ってほしい制約
- **PC の見た目は変えない**（スマホ幅＝〜600px だけの出し分け。既存の表の DOM は残し CSS／薄い表示層で組み替える方針＝見積のスマホ版（`#mcList`）と同じやり方）。
- **機能は消さない**（隠す・畳むのは可。ボタン・並び替え・絞り込み・データは残す）。
- 3 つのテーマ（現行／Industry（既定）／Quiet）で崩れないこと（色は共通トークン）。
- 文字は 12／13／14／16／18px の 5 段（スマホは一段大きい）。タップできるものは **44px 程度**の大きさ。
- 固定ボタン「← 見積もりに戻る」・🐞 常駐ボタンと重ならないこと（下に余白が要る）。
- 書き込みを伴う操作（☆登録・別名・一括置換）は押し間違いに注意（確認の入れ方も案に含めてください）。
