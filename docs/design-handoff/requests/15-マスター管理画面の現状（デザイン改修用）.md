# マスター管理画面の現状（デザイン改修用）— Code → Design

2026-11-12。上段タブ「🗂 マスター管理」（`#tab-master`・中身は `#statsPane-master` と `#statsPane-alias`）のデザインを改修したいので、**今ある機能と見せ方**をまとめます。画像は ZIP の `images/`（数字・名前は試験用の架空データ）。統計画面（14 番）と同じ進め方で、**3 案くらい**お願いします。

## 1. これは何の画面か
- 見積入力で使う「正しい名前」（**マスター**）と、その言い換え（**別名・略称**）を、チームで管理する画面。対象は **サブコン／お客様／品名／港／単位**。
- 入力時の候補（サジェスト）・集計の名寄せ・御見積書の宛先などの元データ。**登録・変更はチーム共有**（Supabase）。管理者と一般メンバーで権限が違う（承認制のときメンバーの登録・別名は「申請」になり、管理者が承認）。
- 使い手：**管理者**（整理・承認）と**見積担当**（探す・詳細を見る・申請する）。スマホで見ることもある。

## 2. 今の構成（上から）

## 3. 一覧のカード（サブコン・お客様）
- 会社名（▸／▾で詳細チップを開閉）＋取引形態チップ（常に表示）＋印（📌 取引ルールN件・⛔厳守・⏳再確認／🗂 事例N件 未解決n／📰 ニュースN件／🤝 紹介したお客様 N社／🔁 サブコンにも登録／🔗 先のお客様 N社）。
- 開くと詳細チップ：ふりがな・担当者（様付き）・所在地・国・タグ・ウェブサイト（リンク）・得意エリア・所属グループ・別名…
- 同業者のカードは**中に先のお客様のカードを入れ子**で表示（何段でも）。
- ボタン：詳細（モーダルを開く）・＋別名・他のマスターにまとめる・別名をすべて外す・使用案件の確認・削除など。

## 4. 詳細ポップアップ（モーダル・幅 最大 980px・高さ固定）
- 上に基本情報（ふりがな・英語名称・取引形態・経由する同業者／先のお客様・紹介元）、下に**タブ**。保存バーは下に常時表示。
- **お客様**：担当者｜会社の詳細・タグ｜顧客カルテ｜取引ルール｜ニュース｜メモ・添付。**サブコン**：担当者｜会社の詳細・種別・エリア｜ニュース｜メモ・添付。港・品名・単位はタブなし（項目が少ない）。
- 担当者は複数名（氏名・ふりがな・部署・役職・電話・E-MAIL・その他連絡・所在地）。タブの見出しに件数の要約（「担当者 3名」など）。
- 取引ルール（守ること・厳守／要確認／メモ）、顧客カルテ（案件ごとの事例＝何が起きた／どう解決した／次回どうすれば良いか）、ニュース（日付つきの時系列）は**1 件ずつ登録するリスト型**。

## 5. 新規登録モーダル
- 種別・マスター名（種別ごとに入力例が変わる）・種別に応じた詳細欄（詳細ポップアップと同じ項目）・「続けて登録する」。Enter で登録・Esc で閉じる。
- 港は別に「📦 港名のプリセットを登録」（国ごとの約 430 港の一覧から選んで一括登録）と「港を一括登録・国を自動で付ける（候補を確認）」。

## 6. 申請・承認（承認制のとき）
- メンバーの「☆ 登録」「→ 別名」「＋ 別名」は**申請**になり、管理者が承認・却下（却下は理由つき）。申請一覧は「記号＋文字」（○ 承認待ち／■ 承認済み／× 却下）。
- 管理者は直接変更できる。マスター名・別名の直接変更は管理者のみ。

## 7. エイリアス是正（小タブ 2）
- 「古い表記 → マスター名」のルールを作り、**過去の案件の表記を一括で書き換える**（取り消しにくい）。実行前に件数を確認し、書き換わる案件の元の内容を JSON で自動ダウンロード（バックアップ）。「バックアップから元に戻す」あり。
- 確認は共通の確認ダイアログ（スマホは下から出るシート）。

## 8. 🔍 ゆらぎチェック（カード）
- 読みが同じ表記は自動で別名にする（管理者のログイン時・週 1 回）／似ている名前は「別名にする・逆にする・≠別物・別の名前にまとめる・保留（30 日）」を選ぶ／代表が複数ある読みは人が判断。履歴・元に戻すあり。

## 9. 今のスマホ（〜600px）で困っていること（要確認）
- 一覧のカードは 1 カラムになるが、**上部（小タブ・ヘッダー・ゆらぎカード・申請・検索・種別チップ・絞り込み・並び順）が縦に長く積み重なり、本題のカードまで遠い**。
- 絞り込みの段が多い（種別→サブ絞り込み 1〜3 段→並び順）。
- ボタンが小さく並ぶ（詳細・＋別名・まとめる・外す・削除）。
- 詳細ポップアップはスマホでは全画面に近いが、タブが 5〜6 個で横に収まらない。

## 10. お願いしたいこと
**3 案くらい**、方向の違う案を（紙芝居でも HTML でも可）。各案に良い点・割り切りも。
- 観点（例）：上部の整理（検索・種別・絞り込み・並び順をどう畳むか）／カードの情報の優先順位（今は印が多い）／詳細ポップアップのタブ（6 つ）の見せ方／申請・承認の見せ方（管理者の「承認待ち」を最優先にしたい）／ゆらぎチェックの置き場所／PC とスマホで共通の考え方にできるか。
- **まず優先して見たい**：①一覧（探す・見つける）②管理者の承認・整理の流れ ③詳細ポップアップ。（違えば教えてください）

## 11. 守ってほしい制約
- **機能は消さない**（畳む・隠すは可。ボタン・絞り込み・並び替え・データは残す）。既存の DOM・`id`・`onclick` は残し、CSS と薄い表示層で組み替える方針（見積・統計のスマホ版と同じ）。
- 3 つのテーマ（現行／Industry（既定）／Quiet）で崩れないこと（色は共通トークン）。文字は 12／13／14／16／18px の 5 段（スマホは一段大きい）。タップは 44px 程度。
- 取り消しにくい操作（削除・一括置換・却下）は確認を入れる（共通の確認ダイアログ `uiConfirm`）。
- 下に 72px の余白（「← 見積もりに戻る」・🐞と重ならない）。

## 12. 参考にできる既存の見せ方
- 統計画面のスマホ版（案B）：今日の確認 → 選ぶシート → カード。
- 見積の費用テーブル（スマホ）：一覧 → タップで編集シート。
- サイバーポート：左で選ぶ・右で流れを見る（スマホは一覧 → 詳細）。
