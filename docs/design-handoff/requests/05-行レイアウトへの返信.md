# 「行レイアウト再整理」案への返信（code → Design）

`ROW-LAYOUT-SPEC.md`・`quote-row-layout-industry.css` を確認しました。**3段固定／同寸法の入力欄／数量・単位の2段／CD は通貨が違う行だけ／更新日は非表示**の方向は、そのまま採用したいです。
チェックボックスが切れる原因（`quote-hierarchy-industry.css` の `tr.subcon-child td:first-child { padding-left }`）は、こちらの CSS でも該当の規則を確認できました。ありがとうございます。

実アプリの構造と突き合わせたところ、**そのままでは取り込めない点が 5 つ**あり、いくつかの判断をお願いしたいです。

## 1. 拡張パネルを「別の `<tr>`」にする案は、実アプリでは危険です（最重要）
`tbody` の子の行は、実アプリで次の 3 種類として扱われています。**行を 1 つ増やすと、どの種類にも当てはまらず、既存の仕組みが壊れます。**

| 種類 | 判定 | 使われ方 |
|---|---|---|
| 明細行 | `data-type` も `data-virtual` も無い（`id="row-N"`） | 並べ替え・複製・削除・保存と復元・合計・グループ表示 |
| 付随行（小計・リマーク） | `data-type="subtotal"／"remark"` | 直前の明細行に付随（`getChildRemarks`）。移動・複製も明細行と一緒 |
| 見出し・小計（仮想行） | `data-virtual="1"` | **再描画（`renderSubconGroups`）のたびに全部削除して作り直す**。保存・出力に含まれない |

- パネルを**仮想行**にすると、再描画のたびに消えます。**パネル内の入力値（有効期間、% モードの率・基準額、CD、フラグ）も一緒に失われます。**
- **仮想行にしない**と、「明細行」と誤認されるか、折りたたみ・除外・並べ替え・複製・削除に追従しません。
- 「行→パネル→次の行」の並びも、↑↓ キー移動やグループの切り出し（`行の直後に付随行が続く`という前提）を崩します。

### 代案（お願い）：パネルは「同じ行（`<tr>`）の中」に置き、行の下に重ねて表示
- 置き場所：`td.name-cell` の内側（行の中）。表示は、つまみの操作ボタン（`.row-acts`）と同じ方式で、**行の下に重ねる**（絶対配置。行の高さは変えない）。
- 幅：行の左端から表の右端まで（`tr` を基準にして `left:0; right:0` 相当）。または、固定幅の大きなパネル。
- 位置：最終行付近は上向きに出す（`tr.is-flip`。JS 側で付与する仕組みは前回実装済み）。
- 開閉：「詳細 ▾」のクリック（`tr.is-detail-open`）。外側クリック・Esc で閉じる。
- 万一この方式が難しい場合の第 2 案：**行の中に縦に展開**（`td.name-cell` の中で、幅 224px のまま下に伸びる。開いている間だけ行が伸びる。クリックで開くので、ちらつきは起きない）。

**依頼：上の「重ねる」方式（第 1 案）のデザインを作ってください。第 2 案も、可能なら併せてお願いします。**

## 2. カテゴリは「文字ラベル」ではなく、選択欄のまま置いてください
案では `.w-cat` を `display:none !important` にして、`.cat-label`（文字）に置き換えています。**これだと、行でカテゴリを変更できなくなります。**
- カテゴリは、見積の並び順（カテゴリ見出し）、色分け、出力に関わる重要な入力です（グループ見出しの「⇅カテゴリ」は、並べ替えのみで、変更はできません）。
- キーボード移動（`data-col="0"`）にも使っています。

**依頼：サブコン／パターン／カテゴリの 3 段目は、`select.w-cat` を高さ 32px にそろえて置いてください**（Industry では、これまで入力中だけ表示していました。常時表示でもよい）。`.cat-label` は不要です。

## 3. 小計・利益のセルは、構造が案の前提と違います
- 小計 `td.subtotal-cell[data-field="st"]` は、**JS が文字・`<br>`・`<small>` を直接書き込んで**います（`div` の子ではありません）。
  - 中身：金額、`<small class="jpy-conv-hint">(≈¥…)</small>`、`<small class="tax-hint">（消費税：…）</small>`、「あえて¥0」`.zero-confirmed-badge`、概算の `.est-prefix`。
- 利益 `td.profit-cell[data-field="pr"]` は、`金額 ＋ <small class="tot-margin">粗利 xx%</small>`。

**案**：こちらの JS 側を、`<div class="st-main">`（金額）／`<div class="st-sub">`（換算の目安）／`<div class="st-sub">`（消費税の目安）、利益は `<div class="pr-main">`／`<div class="pr-rate">` の形に書き出すよう変更します。**このクラス名でデザインしてください**（上の名称で問題なければ、返信は不要です）。

## 4. パネル内の項目が、CSS 自身で隠れます
`.w-valid`（有効期間）、`.row-mode-btns`（フラグ）、`.pct-group`、`.row-cd` は、案の CSS で `#quoteTable` 内では常に `display:none !important` です。パネルは `#quoteTable` の中なので、**パネルの中でも隠れてしまいます。**
**依頼：パネル内（`.row-detail-panel` 内）で再表示する指定（`!important` を含む）を、CSS に含めてください。** 見た目（ラベル、並び、ボタンの大きさ）もお願いします。

## 5. 「状態のしるし」が必要です（Design の質問 2 への回答）
「あえて¥0／実費／PS／必要時／参考／概算」と、「見積書に出さない」「要調査」「入力完了」は、**合計に含めるか・客先に出すかを決める、重要な状態**です。パネルの中に入れると見落とします。現状は次のように見せています。

| 状態 | 現状の見せ方 |
|---|---|
| 実費 | 行の左ライン（青紫）＋価格欄を隠し、`.actual-cost-badge`「実費」 |
| PS（PROFIT SHARE） | 行の左ライン（紫）＋行全体が薄紫、品名が紫 |
| 必要時 | 行の左ライン（橙）＋行の地色 |
| 参考 | 行の左ライン（青）＋行の地色 |
| 概算 | 行の左ライン（緑）＋金額の前に「約」 |
| あえて¥0 | 小計欄に「あえて¥0」 |
| 見積書に出さない（🚫） | 行全体を薄く（半透明）＋品名に打消し線 |
| 要調査 | 行の左ライン（橙）＋つまみ列の地色 |
| 入力完了 | 行の左ライン（緑）＋行の薄緑の地色 |

**依頼：状態を、行に常時見える形で（小さなチップ、または色のライン＋文字）見せる案をください。** 3 段の中に収まる場所（例：3 段目の「詳細 ▾」の右、または行の左ライン＋小チップ）。複数が同時に付くことはほぼありません（実費・PS・必要時・参考は排他）。

## 6. その他（確認・お願い）
- `.w-cur-cost` というクラスは存在しません。通貨の選択欄は、`select.w-cur[data-field="pc"]`（仕）と `select.w-cur.w-cur-sell[data-field="bc"]`（売）です。
- `.w-pattern` は、サブコンのグループ表示で既に「空なら隠す」規則があります。3 段目の割り付けで、サブコン・パターン・カテゴリが同時に必要なとき（グループ見出しにも出ている場合）の見せ方を教えてください。
- **キーボード**：`↑↓` は、同じ `data-col` の次の行へ移動します（`0`＝カテゴリ、`1`＝品名、`2`／`2u`＝数量／単位、`3`／`3b`＝通貨、`4`＝仕入、`5`＝乗せ幅、`6`＝備考）。パネル内の入力欄には `data-col` を付けません（案のとおり）。
- **タッチ**：入口 44px の指定（`@media (hover:none)`）は、こちらで追加します。

## 7. 進め方（2 段階で受け取りたい）
リスクを抑えるため、実装を 2 段階に分けます。CSS も **2 つに分けて**ください。
- **第 1 段階（パネルなし）**：チェックボックスの修正、全入力欄の寸法統一、数量・単位の 2 段、CD の出し分け（通貨が違う行のみ）、更新日の非表示、3 段固定（高さ 116px）、状態のしるし、小計・利益の新しい書き出し。有効期間・マスター登録などは、パネルができるまでの間、**行を伸ばさない位置**（例：品名セルの 3 段目の右に収まる範囲）にとどめる案を。
- **第 2 段階**：「詳細 ▾」とパネル（上の 1・4）、使用中のバッジ。
