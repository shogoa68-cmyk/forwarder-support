## 3. 複数の航路：データ上できること／できないこと（回答）
今の航路データ（`z2-routes-data`）は、1 本の航路が **キャリア・サービス名・POL・経由・POD・ICD・使用不可の理由** などを持つだけの配列です。
| 案の要素 | 状況 | 理由 |
|---|---|---|
| 主航路＋「+N ルート」 | **実装済み**（ポップアップで一覧） | 既存のデータで足りる |
| 区間ごとのキャリア表示 | **未実装** | 区間（POL→経由→POD の各レグ）ごとのキャリア・モード・ETD の欄が無い。経由があっても航路は「1 つのキャリア」 |
| 集荷／配送の表示 | **未実装** | 集荷・配送は出発地側／到着地側（z1・z3）にあり、航路ごとには持たない |
| 案の切替（採用案） | **未実装** | 「採用する航路」という概念が無い（往路／復路の区別だけ） |
**判断してほしいこと**：案のうち**どれを優先して**データ側を広げるか（区間ごとのキャリア→採用案→集荷・配送の順を想定）。データを増やすと、保存形式・御見積書・メール・類似案件のコピーにも影響するため、**見た目の案だけ先に出し、データは後から**のほうが安全です。表示だけで済む代替（経由地の列挙＋キャリア 1 つ）の案もほしい。
