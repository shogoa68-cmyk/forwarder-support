# サイバーポート画面の現状（デザイン改修用）— Code → Design

2026-11-10。上段タブ「🚢 サイバーポート」（`#tab-cptest`）のデザインを改修したいので、**今ある機能と見せ方**をまとめます。画像は ZIP の `images/`（**架空データ**。実際のサイバーポートには接続していません。現行／Industry／Quiet・PC 1440px／スマホ 390px）。

## 1. これは何の画面か
- 国交省系の港湾物流プラットフォーム「サイバーポート（Cyber Port Ver.2）」の情報を、フォワーダー支援から**読み取る**ための画面。
- 今は第 1 段階＝**検証用の最小画面**。**書き込み（送信・返信・編集・削除）は一切しない**（画面にもそう書いてある）。
- 通信はすべて Supabase の中継（Edge Function）経由。接続情報・パスワード・トークンは画面にもブラウザにも出ない。
- 将来像（設計案）：見積・案件（JOB 番号）と取引を結び付け、**動静（本船・コンテナ）を案件の中で見られる**／**取引内のチャットを読める**／新着の通知。いまの画面はその土台。

## 2. 今の画面の構成（上から）
| 区画 | 中身 | 画像 |
|---|---|---|
| ヘッダー | 「🚢 サイバーポート」＋小さく「読み取りのみ（書き込みはしません）」 | cp-classic-initial |
| カード①「接続状態」 | 4 行の状態リスト：サイバーポート API／中継役（Edge Function）／認証（2 つのトークン）／書き込み。**初期はすべて「未確認」（赤）**、「書き込み」だけ「使いません（読み取り専用）」（緑）。①が成功すると上 3 行が緑の「確認済み」になる（確かめていないことを「接続済み」に見せない方針） | cp-classic-ping |
| カード②「🔌 接続・照会」 | 4 つの操作（下の 3 章） | 〃 |
| 結果エリア `#cptLive` | 操作の結果（表・メッセージ・エラー）がカード②の下に 1 か所だけ出る。操作のたびに入れ替わる | 〃 |

## 3. 4 つの操作（ボタンは ①〜④の番号つき）
1. **① 接続情報の確認**（緑の主ボタン）：2 つのトークンが取れるかだけ確かめる（データは取らない）。成功＝緑のメッセージ「✅ 接続情報でトークンを取得できました」＋小さく「トークン取得先／API 接続先」。接続状態の 3 行も緑に。
2. **② 取引を検索**：入力欄 1 つ（取引番号・B/L・ブッキング・社内管理番号。**空なら直近 30 日に更新された取引**）。Enter でも実行。結果は表（取引番号・種別・状態・取引名・B/L・更新日時）。最大 50 行。
3. **③ COLINS 本船の動静**：「輸入／輸出」の選択＋港コード（UN/LOCODE 5 桁・初期値 JPTYO）＋本船名（任意）。結果＝本船ごとの表（**入港予定の早い順**）。
4. **④ COLINS コンテナの状況**：入力欄 1 つ（コンテナ番号／輸入は B/L 番号／輸出はブッキング番号）。③の「輸入／輸出」の選択を共用。結果＝コンテナごとの表。

（②〜④は Enter キーでも実行できる。実行中は 4 つのボタンを無効にして二重押しを防ぐ）

## 4. 結果の表（いちばん情報量が多いところ）
- **本船の動静（③）**：ターミナル（名前＋コード）／本船名／航海番号／IMO／バース／入港 予定・実績／出港 予定・実績／荷役 予定・実績／搬入 予定・実績／CY オープン／CY カット／CFS カット／備考。（約 17 列）
- **コンテナの状況（④）**：輸入と輸出で列が違う。
  - 輸入：ターミナル／コンテナ／サイズ・種類／本船・航海／B/L／実入り・空／通関／検査対象／検査状況／DO 入手／搬出可否／搬出可能／**搬出期限**／デマレージ FT／搬出場所／CY 搬入／ゲートイン／ゲートアウト／**返却期限**／ディテンション FT／返却場所／危険品／備考（約 22 列）
  - 輸出：実入り・空／通関／船積可否／空搬出（場所・予定・実績）／実入り搬入（場所・予定・実績）／ゲートイン／荷役日／船積日／備考
- **表示の決まり**
  - 日時は日本時間 `2026/11/12 11:27`。日付だけの値は時刻なし。読めない値は元の文字のまま。
  - 真偽は ○／×。値が無いセルは空欄。
  - **期限の色分け（重要）**：搬出期限・返却期限・CY カット・CFS カットが、**過ぎている＝赤背景・赤太字**、**あと 48 時間以内＝黄背景・太字**。日付だけの期限はその日の終わりまでを期限とみなす。
  - 表の上に要約の 1 行：「⚠ 搬出期限：超過 1 件・48 時間以内 1 件 ／ 返却期限：…」（輸入のコンテナのみ）。
  - 横に長いので**横スクロール**（`white-space:nowrap`）。最大 50 行。表の列見出しは薄いベージュ。
  - ターミナルコードは名前に変換（初回だけ名前一覧を取る。取れなくてもコードのまま表示）。
  - 最後に「▶ 返ってきたデータそのもの（確認用）」＝折りたたみ（JSON の先頭を等幅で表示。開発・サポート向け）。

## 5. メッセージの種類（結果エリアに出る）
| 種類 | 見た目 | 例 | 画像 |
|---|---|---|---|
| 進行中 | 薄い青の帯 | 「COLINS の本船の動静を取得しています…（輸入・JPTYO）」 | — |
| 成功 | 薄い緑の帯＋緑枠 | 「✅ 接続情報でトークンを取得できました」 | cp-classic-ping |
| 0 件 | 薄い青の帯 | 「番号『NOTHING1』に該当する取引はありません（0件）。」 | cp-classic-empty |
| 入力の誤り | 薄い赤の帯 | 「港コードは、英字2文字＋英数字3文字の5桁で入力してください（例：JPTYO＝東京、JPYOK＝横浜）。」 | cp-classic-validation-error |
| 通信エラー | 薄い赤の帯＋小さな詳細 | 「サイバーポートの応答が不正です」＋「応答コード：502／詳細：…／種類：upstream_error」 | cp-classic-error |
| 想定外の形 | 薄い青の帯＋確認用データ | 「想定と違う形のデータが返りました。…」 | — |

エラーの種類（`code`）：ログインが必要／通信できない／サーバー側が未設定／接続情報が未設定／トークン取得失敗／認証エラー／見つからない／上流エラー／回数制限（1 人 1 分 30 回）／許可されていない API。**日本語で原因と次の行動が分かる文面にしてある**。

## 6. 守ってほしいこと（機能面の制約）
- `id`（`cptPing`／`cptKw`／`cptSearch`／`cptDir`／`cptPort`／`cptVessel`／`cptColinsV`／`cptCtn`／`cptColinsC`／`cptLive`／`cptStApi`／`cptStFn`／`cptStAuth`）とクラス名のうち JS が付け外しするもの（`cpt-st is-ok|is-off`・`cpt-msg is-info|is-ok|is-error`・`cpt-due-over|warn`）は変えない。**画面の HTML は `js/cp-test.js` の `render()` が文字列で組み立てている**ので、構造を変えたい場合は「こういう DOM にしたい」を言ってもらえれば、こちらで組み直します。
- **書き込み系の操作は置かない**（第 1 段階）。将来の「チャット送信」などは別判断。
- 3 テーマ（現行／Industry／Quiet）で見られること。いまは CSS が `#tab-cptest .cpt-*` に限定され、色は共通トークン（`--accent`／`--border`／`--red` など）。Industry・Quiet 専用の整えはしていない（cp-industry-* / cp-quiet-* 参照）。
- 文字は 12px 以上（5 段の文字サイズ・`--text-*`）。スマホは本文 16px。

## 7. 現状の課題（こちらで気づいたこと）
1. **「接続状態」と「操作」の関係が分かりにくい**：状態が「未確認」の赤で並ぶと、エラーに見える。①を押すまでは中立の見せ方（灰色など）にしたい。
2. **①〜④の順番は「手順」ではない**：①は初回の確認、②③④は独立した照会。番号が手順に見える。用途別（取引／本船／コンテナ）に分けたい。
3. **表が横に長い**（22 列）：初期は主要な 6〜8 列だけ出し、残りを「列を増やす」で出す／行を開くと詳細を見せる、などで見やすくしたい。重要なのは **期限（搬出・返却・CY カット）と DO 入手・搬出可否**。
4. **色分けの意味**：赤（超過）・黄（48 時間以内）の凡例が画面に無い。
5. **スマホ**（cp-sp-*）：入力欄とボタンが縦に積み上がり、表が横スクロールのまま。コンテナ 1 件をカード表示にするなど、スマホ向けの見せ方が欲しい。
6. 結果エリアが 1 か所なので、**直前の結果が消える**（3 つの照会を見比べられない）。
7. 開発者向けの要素（「返ってきたデータそのもの」・接続先ホスト名・エラーコード）と一般ユーザー向けの要素が混在。普段は隠したい。

## 8. 今後（実装予定・デザインの前提にしてほしい）
- 案件（見積の管理番号／JOB 番号）と取引の**紐づけ**：見積画面から「この案件の動静」を開く。
- **取引内チャット**の読み取り（メッセージ一覧・新着・未読バッジ・ヘッダー通知）。
- 動静の**自動更新**（Webhook）と通知。
- 「本船の動静」「コンテナの状況」を**案件に紐づけて保存・並べて比較**。
- いまの 4 操作は「検索の入口」になり、結果は案件の中に統合される想定。

## 9. 確認したいこと
- 画面を「**ダッシュボード（案件ごと）**」型にするか、「**照会ツール（検索 → 結果）**」型のままにするか。
- 期限・DO・搬出可否など**重要項目の優先順位**と、通知（赤／黄）の出し方。
- 開発者向け情報（生データ・エラーコード）の置き場所。
- スマホで何をする画面か（確認だけ／入力もする）。
