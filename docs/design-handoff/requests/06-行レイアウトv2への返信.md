`ROW-LAYOUT-SPEC.md`・`quote-row-stage1-industry.css`・`quote-row-stage2-industry.css` を確認しました。**パネルを行の中に置く／カテゴリは選択欄／`.st-*`・`.pr-*` の構造／状態チップ／2 段階の分割**は、そのまま採用します。ありがとうございます。

実アプリの行テンプレート（同梱 `row-template-actual.html`）と突き合わせたところ、**CSS の前提と実構造が合わない点が 5 つ**あります。実装側で補正できるものは補正しますが、見た目に関わるものは、v3 として反映をお願いします。

## 1. Design の質問への回答
### 1-1. パネルの z-index（40）は `.row-acts`（30）より上でよいか
**上で構いません。ただし、重なりの扱いは次のとおりにします。**
- `.row-acts`（つまみの操作ボタン）は、`td.handle-cell` から「行の下端（`top: calc(100% - 2px)`）」に重ねて出しています（`z-index:30`）。パネルも「行の下端（`top:100%`）」から出るため、**左端（約 3 列 × ラベル付きボタン分）で位置が重なります**。
- code 側の方針：`tr.is-detail-open` の間は、`.row-acts` を**出さない**（`opacity:0; pointer-events:none`）。パネルを開いている間は、行の操作ボタンは使えない前提でよいかを教えてください（「詳細」を閉じれば再び出ます）。
- もし「開いたままでも操作したい」場合は、**パネルの左端をつまみ列の右（約 76px = チェック 44px + つまみ 32px）から始め**、`.row-acts` をその左に出す形にしたいです。この場合のパネル幅・余白の案をください。

### 1-2. 第 2 案（行の中で縦展開）は、↑↓ の `data-col` 移動に影響するか
**影響しません。** 移動は「DOM 上で、同じ `data-col` を持つ次の行の入力欄へ」フォーカスを移す仕組みで、行の高さには依存しません。パネル内の入力欄に `data-col` を付けない限り、移動先にもなりません。
- ただし、第 2 案は「開いている間だけ行が伸びる」ため、**表全体の高さが変わり、画面のスクロール位置がずれやすい**点は注意が必要です。第 1 案（重ねる）を主、第 2 案は切替の保険として残す方針とします。

## 2. 実構造と合わない点（v3 で直してほしいもの）
### 2-1. 備考欄の構造（stage1・最重要）
stage1 は `.name-tiers` の子として `.w-note` を 2 段目に置く前提ですが、実際は次のとおりです。
```html
<td class="name-cell">
  <input class="w-name" …>
  <div class="w-note-row">            ← 2段目はこれ
    <input class="w-note" …>
    <button class="btn-row-rem">💬</button>
    <button class="btn-row-int">🔒</button>
  </div>
  <div class="w-valid">…有効 日付〜日付…</div>
  <div class="w-updated">…</div>
  <div class="master-actions">…マスターに登録／詳細…</div>
</td>
```
- `.w-note` は `.w-note-row` の子で、**同じ行に 💬 🔒 の小ボタンが並びます**。stage1 の `width:100%` を `.w-note` にそのまま当てると、ボタンが 2 段目からはみ出します。
- **お願い**：2 段目を `.w-note-row`（備考入力 ＋ 💬 🔒）として設計し直してください（備考入力は残り幅、ボタンは 32px 角など）。
- **確認**：💬 🔒 は、備考欄の文字を引用して直下に備考行・社内メモ行を挿入する、頻出の操作です。**パネルへ移さず、2 段目に残す**案を推奨します（stage2 の `.w-note-aux`／`.note-btn` という class は存在しません）。

### 2-2. `tr.subcon-child` は、グループ表示のときだけ付く class
stage1 の「行の高さ 116px」「チェック修正」は `tr.subcon-child` を前提にしていますが、この class は**サブコン別グループ表示のときだけ**付きます。グループ表示を切った場合も、同じ見た目になる必要があります。
- **お願い**：セレクタを `#quoteTable > tbody > tr:not([data-virtual]):not([data-type])`（＝通常の明細行）に変えてください。付随行（小計・リマーク）と仮想行（見出し・小計）は対象外です。
- 付随行（`data-type=subtotal|remark`）と見出し行の高さは、これまでどおり可変とします。

### 2-3. 第 1 段階だけでは、補助欄が使えなくなる
stage1 は `.w-valid`・`.row-mode-btns`・`.pct-group`・`.row-cd` を行から隠します。第 2 段階（パネル）ができるまでの間、**有効期間・フラグ（あえて¥0／実費／PS／必要時／参考／概算／%）・% モードの入力が、どこからも操作できません**。
- code 側の方針：**第 1・第 2 段階を同じリリースで出します**（段階的に作るが、公開は同時）。この前提で、第 1 段階のデザインレビューでは補助欄が隠れていても構いません。
- 第 1 段階の「3 段目の右」には、`.master-actions`（マスターに登録／詳細）だけを置く、という理解で合っていますか？

### 2-4. 状態チップの優先順位と「同時に付く」ケース
優先順位（出力しない → 要調査 → あえて¥0 → …）は了解です。実アプリでは、**「見積書に出さない」「要調査」「入力完了」は他のフラグ（実費・PS・必要時・参考・概算）と同時に付けられます**（排他なのは、実費・PS・必要時・参考のみ）。
- 「1 つ＋＋n」の「＋n」は、**押すとどうなるか**を決めてください（案：クリックで「詳細 ▾」パネルを開き、状態の一覧を `.rd-flags` で見せる）。
- `.state-chip` の幅は 112px（小計列）に収まる前提ですか。長い語（「見積書に出さない」は「出力しない」に短縮済み、「あえて¥0」「入力完了」）で、「＋n」と並べたときの最小幅を確認してください。

### 2-5. 小計の「3 段目」を状態チップに使うため、消費税の目安の置き場所
v2 は、消費税の目安を `.st-sub` に「≈¥… ／ 税 …」と 1 つにまとめる案でした。実データでは、**円換算の目安（外貨のとき）と、消費税の目安（課税のとき）は、同時に出ることがあります**。1 行（112px）に両方は入りません。
- **お願い**：同時に出る場合の見せ方を決めてください（案：外貨行は円換算の目安を優先し、消費税は `title` のみ／3 段のうち 2 段目を「円換算」、消費税はパネル内の「金額の内訳」に回す）。code 側は、どちらでも書き出せます。
