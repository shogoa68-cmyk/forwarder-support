# 📁 作業フォルダ セットアップ手順（管理者向け）

メンバーごとの個人フォルダ（アプリの「📂 その他 → 📁 作業フォルダ」）を使えるようにするための手順です。**ファイルの中身の置き場は2通り**あり、データベースの設定1つで切り替えられます（画面は同じです）。

| | **A. Supabase 保存領域**（標準・いまの設定） | B. Google ドライブ |
|---|---|---|
| 設定の手間 | **SQL を2つ実行するだけ** | Google Cloud・鍵・Edge Function が必要 |
| 容量 | 小さい（Free プランは全体で 1GB・1ファイル 50MB。ほかの機能と共用） | 大きい（管理者のドライブの分） |
| 定期作業 | なし | 「テスト中」のままなら **毎週、鍵の更新** |
| 1人の上限（初期値） | 50MB | 5GB |

まずは **A** で始めて、容量が足りなくなったら **B** へ切り替える使い方をおすすめします。

---

## A. Supabase 保存領域版（標準）

### 手順 A-1：SQL を 2 つ実行する（5分）

Supabase のダッシュボード → **SQL Editor** で、次の順に貼り付けて **Run** します（何度実行しても安全です）。

1. `docs/sql/work-folders.sql`（フォルダの整理の表・共通の設定）
2. `docs/sql/work-folders-storage.sql`（保存領域の置き場 `work-folders`・アクセス制限・アップロードの入口）

「Success」と出れば完了です。Edge Function や Google の設定は要りません。

### 手順 A-2：動作確認

1. アプリにログインし、「📂 その他 → 📁 作業フォルダ」を開きます。
2. 「新しいフォルダ」を作り、小さなファイルをドラッグ＆ドロップでアップロードします。
3. Supabase の **Storage** に、非公開のバケット **`work-folders`** ができ、ファイルが入っていれば成功です。
4. ダウンロード・プレビュー・ゴミ箱・完全削除（保存領域からも消えること）も試してください。

### 容量の決まりと変え方

- 1人あたり **50MB**、1ファイルも **50MB** までです（Free プランの 1ファイル上限に合わせています）。
- Free プランの保存領域は**全体で 1GB**（記憶に基づく数字です。ダッシュボードの Storage / Usage で確認してください）。不具合報告の画面写真・動画、マスターの添付、ブックマークのファイルと**共用**なので、メンバー数 × 50MB が 1GB に収まるよう注意してください。
- 変えるときは、SQL Editor で次を実行します（例：1人 100MB）。

```sql
update public.wf_config set value = to_jsonb(104857600::bigint) where key = 'quota_bytes_storage';
```

- 使用量を調べる：

```sql
select (storage.foldername(name))[1] as user_id, pg_size_pretty(sum((metadata->>'size')::bigint)) as used
from storage.objects where bucket_id = 'work-folders' group by 1 order by sum((metadata->>'size')::bigint) desc;
```

### 「⚠ 未完了」と出るファイル

アップロードの途中でブラウザを閉じた、通信が切れた、などで残る項目です。中身がまだ入っていないため、開けません。**選んで削除（ゴミ箱→完全に削除）してやり直してください。** 未完了が 10 件たまると、新しいアップロードが止まります。

### Free プランでの注意（Supabase の仕様。記憶に基づくので、最新はダッシュボードで確認してください）

- Free プランのプロジェクトは、**1週間まったく使われないと一時停止**されることがあります（Supabase の仕様。ダッシュボードで再開できます）。
- バックアップは付きません。大事なファイルは、ほかの場所にも控えを置いてください。

### 確認していないこと（実装時点）

SQL（予約・確定・容量・アクセス制限）は、PostgreSQL 上に Supabase の仕組みを簡易に再現して実際に流して確かめました（`scripts/sql-tests/work-folders-sql-test.sh`）。画面の操作は、Supabase を模擬した環境で自動テストしています（`scripts/design-tests/workfolder-storage-test.js`）。**本物の Supabase の保存領域との接続は、手順 A-2 が初めての実機確認**です。特に次の点を見てください。

- 数十 MB のファイルが最後までアップロードできること（Supabase は 6MB を超えるファイルに別の方式を勧めています。うまくいかなければ教えてください）。
- 日本語名のファイルをダウンロードしたとき、保存名が正しいこと。

## B. Google ドライブ版（容量が足りなくなったとき）

次の手順 1〜5 で用意し、最後に**手順 6 で置き場を切り替えます**。（手順 1 の SQL は、A で実行済みなら不要です。）

> ⚠️ **Google の「テスト中」のまま使う前提です。** テスト中のアプリが発行する鍵は **7日で切れる**ため、**1週間に1回、管理者が鍵を取り直す作業（約5分）が必要**です（→「毎週の鍵の更新」）。切れると、メンバーの画面に「管理者のドライブとの接続が切れています」と出ます。
> 「本番環境」にすれば更新は不要になりますが、Gmail（個人）のアカウントでは公開の手続きに追加の準備が要るため、「テスト中」で始める方針にしています。

### しくみ（ドライブ版）

```
メンバーの画面 ──(ログイン中の本人だけ)──▶ Edge Function「workfolder」 ──(管理者の鍵)──▶ 管理者の Google ドライブ
        │                                          │
        └────────── 整理の情報（どのフォルダに何があるか）は Supabase の wf_nodes 表 ◀──┘
```

- **ファイルの中身**は、管理者の Google ドライブに置かれます。持ち主はいつも管理者なので、**管理者のドライブの容量**が使われます。
- メンバーは Google ドライブを直接さわりません。必ず Edge Function（Supabase の中で動く小さなプログラム）を通ります。
- **「どのフォルダにあるか」「名前」「サイズ」**は Supabase の表で管理します。名前の変更・移動・ゴミ箱は表を書き換えるだけなので一瞬です。
- 自分のファイルは自分だけに見えます（共有機能はありません）。1人の上限は **5GB** です。

> 用語：
> - **OAuth** … 「このアプリに、私のドライブを使わせてよい」と Google に許可を出す仕組みです。
> - **リフレッシュトークン** … その許可を長持ちさせる「合鍵」です。**このリポジトリ（公開されています）には絶対に書かないでください。** Supabase の「秘密の設定（secrets）」にだけ置きます。
> - **Edge Function** … Supabase 上で動く、サーバー側の小さなプログラムです。

## 手順 1：Supabase にテーブルを作る（5分）

1. Supabase のダッシュボード → **SQL Editor** を開きます。
2. `docs/sql/work-folders.sql` の中身を貼り付けて **Run** します（何度実行しても安全です）。
3. 「Success」と出れば完了です。

## 手順 2：Google Cloud で「ドライブを使う許可の入口」を作る（15分）

使うのは、**容量を分け与えたいドライブの持ち主（管理者）の Google アカウント**です。

1. <https://console.cloud.google.com/> を開き、新しいプロジェクトを作ります（名前は何でも可。例：`forwarder-workfolder`）。
2. 左メニュー **APIとサービス → ライブラリ** で **Google Drive API** を検索して **有効にする**。
3. **OAuth 同意画面**（「Google Auth Platform」と表示される場合もあります）を設定します。
   - ユーザーの種類：Gmail（個人）なら **外部**（Google Workspace なら「内部」も選べ、その場合は鍵が切れません）。
   - **ブランディング**：必須の **アプリ名**・**ユーザー サポートメール**・**デベロッパーの連絡先メール** だけ入力して保存します。ロゴ・ホームページ・プライバシーポリシー・利用規約・承認済みドメインは**入れません**（入れると Google の審査が必要になることがあります）。
   - **データアクセス（スコープ）**に `https://www.googleapis.com/auth/drive.file` を追加します。
     - これは「**このアプリが作ったファイルだけ**見られる」という弱い権限です。管理者のドライブの他のファイルには触れません。
   - **公開ステータスは「テスト中」のままにします。**
   - **「対象（Audience）」→「テストユーザー」に、管理者本人の Gmail アドレスを追加します**（追加しないと、手順3で「アクセスをブロック」と出てログインできません）。
4. **認証情報 → 認証情報を作成 → OAuth クライアント ID** を選びます。
   - アプリケーションの種類：**ウェブ アプリケーション**
   - **承認済みのリダイレクト URI**：`https://developers.google.com/oauthplayground`
   - 作成すると **クライアント ID** と **クライアント シークレット** が表示されるので、メモします。

## 手順 3：合鍵（リフレッシュトークン）を取り出す（5分）

1. <https://developers.google.com/oauthplayground> を開きます。
2. 右上の歯車 ⚙ を押し、**Use your own OAuth credentials** にチェックを入れて、手順 2 の **クライアント ID** と **クライアント シークレット** を入力します。
3. 左の **Step 1** の入力欄に `https://www.googleapis.com/auth/drive.file` と入力し、**Authorize APIs** を押します。
4. **管理者のアカウント**でログインし、許可します。
5. **Step 2** の **Exchange authorization code for tokens** を押し、表示される **Refresh token** をメモします。

> 途中で「Google はこのアプリを確認していません」と出ても、管理者本人のアカウントなので **「詳細」→「（アプリ名）に移動」→ 許可** で進めます。
> この鍵は**テスト中のため 7 日で切れます**。切れたら同じ手順をやり直します（→「毎週の鍵の更新」）。

## 手順 4：Supabase に鍵を預けて Edge Function を置く（10分）

[Supabase CLI](https://supabase.com/docs/guides/cli) が使える PC で、このリポジトリのフォルダから実行します。

```bash
supabase login
supabase link --project-ref <プロジェクトの参照ID>
```

秘密の設定を入れます（`<…>` は自分の値に置き換えます）。

```bash
supabase secrets set GOOGLE_CLIENT_ID=<手順2のクライアントID> GOOGLE_CLIENT_SECRET=<手順2のシークレット> GOOGLE_REFRESH_TOKEN=<手順3のリフレッシュトークン>
```

画面を公開している URL を「許可するアクセス元」として登録します（カンマ区切り。例は GitHub Pages とローカル確認用）。

```bash
supabase secrets set WF_ALLOWED_ORIGINS=https://<公開URL>,http://localhost:18765
```

Edge Function を置きます。

```bash
supabase functions deploy workfolder --no-verify-jwt
```

> `--no-verify-jwt` は「入口の門番を外す」意味ではありません。`workfolder` は中で**自分でログインの確認とチームメンバーの確認**をしています（そうしないと、ブラウザの事前確認の通信がはじかれて動かないことがあるため）。

オプション：1ファイルの上限は初期値 2GB です。変えたいときは `supabase secrets set WF_MAX_FILE_BYTES=<バイト数>` を使います。

## 手順 5：動作確認

1. アプリにログインし、「📂 その他 → 📁 作業フォルダ」を開きます。
2. 「新しいフォルダ」を作り、小さなファイルをドラッグ＆ドロップでアップロードします。
3. 管理者のドライブに **「フォワーダー支援 作業フォルダ」** というフォルダが自動で作られ、その中にファイルが入っていれば成功です。
4. ダウンロード・プレビュー・ゴミ箱・完全削除（ドライブからも消えること）も一通り試してください。

---

## 手順 6：置き場をドライブに切り替える

手順 5 の動作確認が済んだら、SQL Editor で次を実行します。

```sql
update public.wf_config set value = '"drive"'::jsonb where key = 'backend';
```

これで、全員の作業フォルダの置き場がドライブになり、1人の上限は 5GB（`quota_bytes_drive`）になります。Supabase の保存領域に**すでに入れたファイルは、自動では移りません**（切り替えると開けなくなります）。切り替える前に、必要なファイルはダウンロードして控えてください。Supabase 版に戻すときは `'"storage"'` にします。

## 毎週の鍵の更新（ドライブ版・約5分・1週間に1回）

テスト中の鍵は 7 日で切れるため、**取得した日から数えて 6 日目あたりに更新**するのがおすすめです（カレンダーに毎週の予定を入れておくと忘れません）。

1. <https://developers.google.com/oauthplayground> を開き、手順 3 と同じ操作をします（歯車で自分の OAuth 認証情報を使う設定 → Step 1 で `https://www.googleapis.com/auth/drive.file` → 管理者のアカウントでログイン → Step 2 で **Refresh token** を取得）。
2. 新しい鍵を Supabase に預けます。

```bash
supabase secrets set GOOGLE_REFRESH_TOKEN=<新しいリフレッシュトークン>
```

3. 作業フォルダを開いて、小さなファイルが上げられるか確認します。**Edge Function を置き直す必要はありません**（鍵は呼び出しのたびに読み直します）。

> 鍵の更新を忘れても、**すでにアップロード済みのファイルや整理の情報は消えません。** 更新するまで、アップロード・ダウンロード・完全削除ができなくなるだけです（フォルダの作成・名前変更・移動・ゴミ箱は使えます）。
> この毎週の作業をなくしたいときは、Google の公開ステータスを「本番環境」にします（プライバシーポリシー等のページを用意して公開の手続きを進める必要があるかもしれません。必要になったら相談してください）。

## 運用メモ（ドライブ版）

| こと | 内容 |
|---|---|
| 上限（5GB）を変えたい | Supabase の SQL Editor で `update wf_config set value = to_jsonb(10737418240::bigint) where key = 'quota_bytes_drive';`（10GB の例） |
| 使用量を調べたい | `select owner_email, pg_size_pretty(sum(size)) from wf_nodes where kind = 'file' group by 1 order by sum(size) desc;`（ドライブ版・保存領域版の両方の合計） |
| ドライブ側の見え方 | ファイルは「フォワーダー支援 作業フォルダ」の中に**フラット（階層なし）**で並びます。アプリ内のフォルダ構造・名前変更はドライブには反映されません（アプリの表で管理しているため）。 |
| ゴミ箱 | アプリのゴミ箱に入れただけでは、ドライブの容量は空きません。「完全に削除」でドライブからも消えます。 |
| 鍵が使えなくなったとき | テスト中は **7 日で切れる**のが通常です。メンバーの画面に「管理者のドライブとの接続が切れています」と出たら、下の「毎週の鍵の更新」を行ってください。ほかに、管理者のパスワード変更・アプリの許可の取り消し・6か月以上の未使用でも切れます。 |
| 取り残しファイル | アップロードの途中でブラウザを閉じると、ドライブにだけファイルが残ることがあります（アプリには表示されず、容量だけ使います）。ドライブの「フォワーダー支援 作業フォルダ」を時々のぞいて、アプリに無い古いファイルは手で消せます。 |
| 大きなファイル | ダウンロードとプレビューはブラウザのメモリにいったん読み込みます。数 GB のファイルは重くなります。 |
| 共有ドライブ（Workspace）に変えたいとき | 保存先フォルダの指定（`wf_config` の `drive_root_id`）と Drive API の呼び出しに `supportsAllDrives=true` を足す小さな改修で対応できます。必要になったら相談してください。 |

## 確認していないこと（ドライブ版・実装時点）

この機能は、画面の操作（フォルダ作成・名前変更・移動・ゴミ箱・アップロードの流れ・検索・プレビューなど）を、Supabase とドライブを**模擬した環境**で自動テストしています（`scripts/design-tests/workfolder-test.js`）。**本物の Google ドライブ・Supabase Edge Function との接続は、手順 5 の確認が初めての実機確認**になります。特に次の点を見てください。

- ブラウザからドライブへ直接アップロードできること（Google 側の通信許可＝CORS に関わるため）
- 日本語のファイル名でダウンロードしたとき、保存名が正しいこと
