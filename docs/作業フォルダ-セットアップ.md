# 📁 作業フォルダ セットアップ手順（管理者向け）

メンバーごとの個人フォルダ（アプリの「📂 その他 → 📁 作業フォルダ」）を使えるようにするための、**最初に1回だけ行う準備**です。

## しくみ（先に読むと迷いません）

```
メンバーの画面 ──(ログイン中の本人だけ)──▶ Edge Function「workfolder」 ──(管理者の鍵)──▶ 管理者の Google ドライブ
        │                                          │
        └────────── 整理の情報（どのフォルダに何があるか）は Supabase の wf_nodes 表 ◀──┘
```

- **ファイルの中身**は、管理者の Google ドライブに置かれます。持ち主はいつも管理者なので、**管理者のドライブの容量**が使われます。
- メンバーは Google ドライブを直接さわりません。必ず Edge Function（Supabase の中で動く小さなプログラム）を通ります。
- **「どのフォルダにあるか」「名前」「サイズ」**は Supabase の表で管理します。名前の変更・移動・ゴミ箱は表を書き換えるだけなので一瞬です。
- 自分のファイルは自分だけに見えます（共有機能はありません）。1人の上限は **5GB** です。

> 用語：
> - **OAuth** … 「このアプリに、私のドライブを使わせてよい」と Google に許可を出す仕組みです。
> - **リフレッシュトークン** … その許可を長持ちさせる「合鍵」です。**このリポジトリ（公開されています）には絶対に書かないでください。** Supabase の「秘密の設定（secrets）」にだけ置きます。
> - **Edge Function** … Supabase 上で動く、サーバー側の小さなプログラムです。

---

## 手順 1：Supabase にテーブルを作る（5分）

1. Supabase のダッシュボード → **SQL Editor** を開きます。
2. `docs/sql/work-folders.sql` の中身を貼り付けて **Run** します（何度実行しても安全です）。
3. 「Success」と出れば完了です。

## 手順 2：Google Cloud で「ドライブを使う許可の入口」を作る（15分）

使うのは、**容量を分け与えたいドライブの持ち主（管理者）の Google アカウント**です。

1. <https://console.cloud.google.com/> を開き、新しいプロジェクトを作ります（名前は何でも可。例：`forwarder-workfolder`）。
2. 左メニュー **APIとサービス → ライブラリ** で **Google Drive API** を検索して **有効にする**。
3. **OAuth 同意画面**（「Google Auth Platform」と表示される場合もあります）を設定します。
   - ユーザーの種類：個人の Gmail なら **外部**、Google Workspace なら **内部** でも可です。
   - アプリ名・サポートメールを入力します。
   - **スコープ**に `https://www.googleapis.com/auth/drive.file` を追加します。
     - これは「**このアプリが作ったファイルだけ**見られる」という弱い権限です。管理者のドライブの他のファイルには触れません。
   - **外部**を選んだ場合は、公開ステータスを「**本番環境（In production）**」にします。
     - 「テスト」のままだと、**7日で鍵が切れて**作業フォルダが突然使えなくなります。
     - `drive.file` は審査が要らない種類のスコープなので、本番にしても審査待ちにはなりません（「未確認のアプリ」という警告が出ることがありますが、管理者本人が承認するだけなので問題ありません）。
4. **認証情報 → 認証情報を作成 → OAuth クライアント ID** を選びます。
   - アプリケーションの種類：**ウェブ アプリケーション**
   - **承認済みのリダイレクト URI**：`https://developers.google.com/oauthplayground`
   - 作成すると **クライアント ID** と **クライアント シークレット** が表示されるので、メモします。

## 手順 3：合鍵（リフレッシュトークン）を取り出す（5分）

1. <https://developers.google.com/oauthplayground> を開きます。
2. 右上の歯車 ⚙ を押し、**Use your own OAuth credentials** にチェックを入れて、手順 2 の **クライアント ID** と **クライアント シークレット** を入力します。
3. 左の **Step 1** の入力欄に `https://www.googleapis.com/auth/drive.file` と入力し、**Authorize APIs** を押します。
4. **管理者のアカウント**でログインし、許可します。
5. **Step 2** の **Exchange authorization code for tokens** を押し、表示される **Refresh token** をメモします。

## 手順 4：Supabase に鍵を預けて Edge Function を置く（10分）

[Supabase CLI](https://supabase.com/docs/guides/cli) が使える PC で、このリポジトリのフォルダから実行します。

```bash
supabase login
supabase link --project-ref <プロジェクトの参照ID>
```

秘密の設定を入れます（`<…>` は自分の値に置き換えます）。

```bash
supabase secrets set GOOGLE_CLIENT_ID=<手順2のクライアントID> GOOGLE_CLIENT_SECRET=<手順2のシークレット> GOOGLE_REFRESH_TOKEN=<手順3のリフレッシュトークン>
```

画面を公開している URL を「許可するアクセス元」として登録します（カンマ区切り。例は GitHub Pages とローカル確認用）。

```bash
supabase secrets set WF_ALLOWED_ORIGINS=https://<公開URL>,http://localhost:18765
```

Edge Function を置きます。

```bash
supabase functions deploy workfolder --no-verify-jwt
```

> `--no-verify-jwt` は「入口の門番を外す」意味ではありません。`workfolder` は中で**自分でログインの確認とチームメンバーの確認**をしています（そうしないと、ブラウザの事前確認の通信がはじかれて動かないことがあるため）。

オプション：1ファイルの上限は初期値 2GB です。変えたいときは `supabase secrets set WF_MAX_FILE_BYTES=<バイト数>` を使います。

## 手順 5：動作確認

1. アプリにログインし、「📂 その他 → 📁 作業フォルダ」を開きます。
2. 「新しいフォルダ」を作り、小さなファイルをドラッグ＆ドロップでアップロードします。
3. 管理者のドライブに **「フォワーダー支援 作業フォルダ」** というフォルダが自動で作られ、その中にファイルが入っていれば成功です。
4. ダウンロード・プレビュー・ゴミ箱・完全削除（ドライブからも消えること）も一通り試してください。

## 運用メモ

| こと | 内容 |
|---|---|
| 上限（5GB）を変えたい | Supabase の SQL Editor で `update wf_config set value = to_jsonb(10737418240::bigint) where key = 'quota_bytes';`（10GB の例） |
| 使用量を調べたい | `select owner_email, pg_size_pretty(sum(size)) from wf_nodes where kind = 'file' group by 1 order by sum(size) desc;` |
| ドライブ側の見え方 | ファイルは「フォワーダー支援 作業フォルダ」の中に**フラット（階層なし）**で並びます。アプリ内のフォルダ構造・名前変更はドライブには反映されません（アプリの表で管理しているため）。 |
| ゴミ箱 | アプリのゴミ箱に入れただけでは、ドライブの容量は空きません。「完全に削除」でドライブからも消えます。 |
| 鍵が使えなくなったとき | 管理者のパスワード変更・アプリの許可の取り消し・6か月以上の未使用などで鍵が失効します。「⚠️ ドライブへの接続に失敗しました」と出たら、**手順 3 をやり直して** `supabase secrets set GOOGLE_REFRESH_TOKEN=…` を更新してください。 |
| 取り残しファイル | アップロードの途中でブラウザを閉じると、ドライブにだけファイルが残ることがあります（アプリには表示されず、容量だけ使います）。ドライブの「フォワーダー支援 作業フォルダ」を時々のぞいて、アプリに無い古いファイルは手で消せます。 |
| 大きなファイル | ダウンロードとプレビューはブラウザのメモリにいったん読み込みます。数 GB のファイルは重くなります。 |
| 共有ドライブ（Workspace）に変えたいとき | 保存先フォルダの指定（`wf_config` の `drive_root_id`）と Drive API の呼び出しに `supportsAllDrives=true` を足す小さな改修で対応できます。必要になったら相談してください。 |

## 確認していないこと（実装時点）

この機能は、画面の操作（フォルダ作成・名前変更・移動・ゴミ箱・アップロードの流れ・検索・プレビューなど）を、Supabase とドライブを**模擬した環境**で自動テストしています（`scripts/design-tests/workfolder-test.js`）。**本物の Google ドライブ・Supabase Edge Function との接続は、手順 5 の確認が初めての実機確認**になります。特に次の点を見てください。

- ブラウザからドライブへ直接アップロードできること（Google 側の通信許可＝CORS に関わるため）
- 日本語のファイル名でダウンロードしたとき、保存名が正しいこと
