## 目的（合意済み）
- フォワーダー支援から、サイバーポートの **取引内チャット** と **動静確認** を使えるようにする
- 第1段階は **読み取りのみ**（書き込みはしない）
- 中継役は **Supabase**（Edge Function）

## 全体構成（案）
```
ブラウザ（フォワーダー支援）
   │  Supabaseログイン済みの人だけ呼べる
   ▼
Supabase Edge Function「cp-proxy」  ← 接続情報（秘密）はここだけに置く
   │  読み取りAPIのみ許可（ホワイトリスト）
   ▼
サイバーポート API (Ver.2)

サイバーポート ──Webhook──▶ Edge Function「cp-webhook」（署名照合）──▶ Supabaseテーブル ──▶ ブラウザ（Realtime）
```
- 接続情報は Supabase のシークレットに保存。`cloud-config.js` や GitHub には絶対に置かない。
- 第1段階で `cp-proxy` が通すのは **GET だけ**（チャットなら `Messages/GetDetails`・`Messages/GetHistories`）。`Send`・`Reply`・`Edit`・`MarkAsDelete` は許可リストに入れない。
- `cp-proxy` は `is_team_member()` に合格した人だけ使える。連携専用アカウントで通信する（更新履歴に個人名が出るのを防ぐ）。
- フロント側の呼び出しは `js/integrations/cyberport.js` の1か所に集める（PRODUCT_VISION の「データアクセス層を1か所に」に沿う）。

## テーブル案
- `cp_deal_links`：自社JOB番号 ⇔ サイバーポート取引管理番号（EXP_/IMP_…）の対応
- `cp_events`：Webhook受信ログ（種別・取引番号・受信時刻・本文）。チャット新着や動静更新の通知元
- `cp_cache`：照会結果の短期キャッシュ（同じ番号を何度も呼ばないため）

## 段階
1. **読み取り（動静）**：JOB番号またはB/L番号から取引を引き、動静を表示。まずボタン1つの手動照会
2. **読み取り（チャット）**：取引ごとのチャットを表示。Webhook受信後に自動更新
3. 通知：未読バッジ・ヘッダーの通知
4. （将来・別判断）チャット送信などの書き込み。やるなら Get-Then-Register を守り、サンドボックスで先に検証

## 実装状況（2026-11-10・第1段階）
- **Edge Function `cp-proxy`**（`supabase/functions/cp-proxy/`）：**2つのトークン**（①システム用 `X-Authorization`・②利用者用 `Authorization: Bearer`）を公式の方法で取り、許可リストの GET だけを呼ぶ。ログイン済みチームメンバーのみ・1人1分30回まで・相手先エラーは最大3回の指数バックオフ・401 はトークンを両方取り直して1回だけやり直す。利用者トークンは read スコープのみ。本番／検証環境は `CP_ENV` で切り替え。接続情報・パスワード・トークンは応答にもログにも出さない。
- **ブラウザ側の窓口** `js/integrations/cyberport.js`（`CyberPort.ping()`／`get()`／`tradesSearch()` ほか）。
- **CP(TEST)** に「🔌 実接続テスト」：① 接続情報の確認（トークンが取れるか）② 取引の検索（番号 or 直近30日）。サンプル欄とは分けて表示。
- 手順：[サイバーポート連携-セットアップ.md](サイバーポート連携-セットアップ.md)。試験：`scripts/cp-tests/`（サイバーポートへは接続しない偽の通信で検証）。
- **実機で確認できたこと**：トークン取得先（`/vendor-auth/token` は swagger ホスト）、CORS（公開サイトからの呼び出し）、システム用トークンの取得まで。**利用者用トークン（橋渡しユーザー）を足した版**で、`Trades/Search` の読み取りを確認するところ（引き継ぎ書 第6章の公式仕様で実装）。

## 検証シートから取り込むべき注意（読み取りでも効くもの）
- 番号は空白除去して正規化（`ONEY TYOGF8748400` → `ONEYTYOGF8748400`）
- 失敗時は最大3回まで間隔を延ばして再試行
- 「NACCS未登録（ETA前）」と「通信エラー」は別メッセージで出す
- M3・重量は丸めない（文字列/Decimalで扱う）
- 船会社コード（SCAC）・荷姿コードの変換表は Drive の「SCAC一覧（FNxCP連携用）」を使う
- 輸入LCLの搬入場所は「蔵置場所コード」（FCLは船卸場所コード）
