# デザインルール（デザイントークン）

サイトの見た目の「決まり事」を、名前つきの値（CSS 変数）として `フォワーダー支援/css/tokens.css` に集約している。
見た目を変えるときは、まずここの値を変える。Claude Design とは、この表をルールとして共有する。
変更の前後の確認は [デザイン変更の安全手順](デザイン変更の安全手順.md) に従う。

## 方針
1. **現状をルール化してから変える**：まず、いまの色をそのまま名前にする（見た目は変えない）。変更はその後。
2. **基準はいまのベージュ・茶系**（`DESIGN_VISION.md` の白・グレー系は、将来の変更候補として別に検討する）。
3. 見た目を変えない置き換えは、**証明つき**で行う（下記の `--verify`）。

## 進捗
- **2a（完了）**：使用回数の多い 42 色を、見た目を変えずにトークンへ置き換え（`css/style.css`・`css/quote.css`の 2,106 か所）。
  色の直書きは 5,367 か所 → 3,261 か所（約 39% がトークン経由）。残りは使用回数の少ない色が約 1,500 種類。
- **2b（次）**：ごく近い色（人の目ではほぼ区別できない差）を既存のトークンへ寄せる。わずかな見た目の差が出るため、画面の比較で確認しながら進める。
- **2c**：文字の大きさ・余白・角の丸み・影をトークン化。
- **3**：整えたルールを Claude Design へ共有（`/design-sync`）。

## 道具
| 目的 | コマンド |
|---|---|
| 色の使用回数の上位と、トークン化の状況 | `node scripts/tokenize-css.js --list 60` |
| tokens.css の色を CSS の直書きから置き換える | `node scripts/tokenize-css.js --apply` |
| 置き換えで色が 1 つも変わっていないことの証明 | `node scripts/tokenize-css.js --verify [git参照]` |

`--verify` は、置き換え後の CSS の `var(--名前)` を元の色へ戻し、基準（git の指定版）の CSS と完全に一致するかを調べる。
一致すれば、どの規則・どの状態でも色が 1 つも変わっていないことの証明になる（画面のスクリーンショット比較より強い確認）。
