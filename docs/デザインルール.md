# デザインルール（デザイントークン）

見た目の「決まり事」を、名前つきの値（CSS 変数）として集約している。**2 系統**に分けて持つ。

| 系統 | ファイル | 対象 |
|---|---|---|
| サイト画面 | `フォワーダー支援/css/tokens.css` | 画面全体の色（`style.css`・`quote.css` が使う） |
| 御見積書 | `フォワーダー支援/css/tokens-doc.css` | お客様に出す御見積書（PDF・プレビュー）の色・書体・文字の大きさ・用紙寸法（`quote-pdf.css` と、御見積書の HTML が使う） |

**御見積書はサイトとは独立**：サイトの配色を変えても、御見積書は変わらない（御見積書のデザインを変えるときは、`tokens-doc.css` の値を変える）。
見た目を変えるときは、まず該当するトークンの値を変える。Claude Design とは、この表をルールとして共有する。
変更の前後の確認は [デザイン変更の安全手順](デザイン変更の安全手順.md) に従う。

## 方針
1. **現状をルール化してから変える**：まず、いまの色をそのまま名前にする（見た目は変えない）。変更はその後。
2. **基準はいまのベージュ・茶系**（`DESIGN_VISION.md` の白・グレー系は、将来の変更候補として別に検討する）。
3. 見た目を変えない置き換えは、**証明つき**で行う（下記の `--verify`）。

御見積書の CSS（`quote-pdf.css` の「A4 御見積書本体」以降）の色・書体・文字の大きさ・用紙寸法 128 か所と、
御見積書の HTML に直接書かれていた 4 か所の指定を、このトークンへ置き換え済み（見た目の変更なし）。
画面の PDF 出力設定パネル（`quote-pdf.css` の先頭側）は、サイト画面の一部なので `tokens.css` の側で今後整理する。

## 進捗
- **2a（完了）**：使用回数の多い 42 色を、見た目を変えずにトークンへ置き換え（`css/style.css`・`css/quote.css`の 2,106 か所）。
  色の直書きは 5,367 か所 → 3,261 か所（約 39% がトークン経由）。残りは使用回数の少ない色が約 1,500 種類。
- **御見積書のルール化（完了）**：上記。サイトとは独立した系統として整備。
- **2b（完了）**：ごく近い色（色差 ΔE≤4）を既存トークンへ統合。直書きの色 3,261 → 1,965 か所（色の種類 1,497 → 1,004）。
  変化した 1,233 か所はすべて ΔE≤4（最大 3.99）、色以外は 1 文字も変わっていない（`--verify-snap 4`）。画面の差は最大 0.39% の画素。
  色のルール経由は全体の約 63%。残りは使用 1〜数回の一点ものの色（約 1,000 種類）で、必要に応じて個別に整理する。
- **2c（完了）**：文字の大きさ・角の丸み・余白を、見た目を変えずにトークン化（`css/style.css`・`css/quote.css` の 6,237 か所。`--verify` で完全一致を確認、画面の差なし）。
  影（box-shadow）は 100 種類以上あり共通化の効果が薄いため、今回は対象外。
- **3**：整えたルールを Claude Design へ共有（`/design-sync`）。

## 道具
| 目的 | コマンド |
|---|---|
| 色の使用回数の上位と、トークン化の状況 | `node scripts/tokenize-css.js [--profile doc] --list 60` |
| 近い色の統合の候補／寄せ／変化量の保証 | `--plan-colors T N [--write]` ／ `--snap-colors T` ／ `--verify-snap T [git参照]` |
| トークンの値を CSS の直書きから置き換える | `node scripts/tokenize-css.js [--profile doc] --apply` |
| 置き換えで値が 1 つも変わっていないことの証明 | `node scripts/tokenize-css.js [--profile doc] --verify [git参照]` |

`--profile doc` が御見積書の系統（省略するとサイト画面）。

`--verify` は、置き換え後の CSS の `var(--名前)` を元の色へ戻し、基準（git の指定版）の CSS と完全に一致するかを調べる。
一致すれば、どの規則・どの状態でも色が 1 つも変わっていないことの証明になる（画面のスクリーンショット比較より強い確認）。

## Claude Design への共有
共有用の一式を `docs/design-system/` に生成する（`node scripts/build-design-system.js`）。
- `README.md`：アプリの説明・ルールの一覧・デザインを変えるときの約束（部品名を残す等）
- `css/`：ルール（`tokens.css`・`tokens-doc.css`）と、実際の画面の CSS
- `cards/`：見本カード 13 枚（色・文字・角の丸み/余白・主要な部品・御見積書 3 種）。部品は実際の画面から取り出した HTML

共有は、お客様が `/design-sync` を開始し、計画を承認して行う。デザインを変えたら、再生成して差し替える。
