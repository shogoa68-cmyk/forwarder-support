# マニュアルを最新にする（/update-manual）

引数：`$ARGUMENTS`
- 章の id（例 `quote-rows`）＝その章だけ見直す
- 空・`all` ＝ 見張りで見つかったもの（説明の無い画面・見直しが要る章）をすべて

## 守ること（最初に読む）
- このリポジトリは**公開**。お客様名・社内の情報・本物の金額・メールアドレスは原稿に**書かない**（例は「○○商事」「USD 1,200」）。
- 読む人は**新人**（小学校高学年〜中学生にも分かる言葉）。ボタン名は画面の表記どおり `` `保存` `` で囲む。推測で操作を書かない：**必ずコード（index.html・js）を読んで、実在するボタン名・手順だけ書く**。
- `フォワーダー支援/data/manual.js` は手で直さない（原稿を直して作り直す）。
- 自動でマージしない。PR は頼まれたときだけ（定期実行から呼ばれたときは、その指示に従う）。

## 手順
1. 同期：`git fetch origin main && git merge origin/main`（浅い取得なら先に `git fetch --unshallow origin`。見直しの判定に履歴が要る）。
2. 見張り：`node scripts/build-manual.js --check`（JSON が欲しければ `--check --json`）。
   - ① まだ説明の無い画面 → 新しい章を `docs/マニュアル/NN-名前.md` に作る（書き方は `docs/マニュアル/README.md`）。`covers` にその画面の `tab-…` を入れる。
   - ② 見直しが要る章 → 表示されたコミットを `git show <hash> --stat` と差分で読み、画面の文言・手順・ボタン名が変わった所だけ本文を直す。変わっていなければ本文はそのまま。どちらでも、見直したら `updated` を今日の日付にする。
   - ③ 原稿の誤り → 直す。
   - 関係するプログラムが増えたら `watch` に足す（大きすぎる `index.html` は入れない）。
3. 練習（```lesson）の場所（セレクタ）が今も画面にあるか、コードで確かめる。無くなっていれば直すか `else:` を足す。
4. 作り直し：`node scripts/build-manual.js`（終わりに「見直し待ち 0」になっていること）。
5. 試験：`node scripts/manual-tests/manual-md-test.js` と `node scripts/design-tests/manual-test.js`（`W=390` も）。
6. CLAUDE.md の「📘 マニュアル」の節に、仕組みが変わったときだけ追記する。
7. commit（メッセージは「マニュアル：○○の章を見直し」など）→ 自分の作業ブランチへ push。

## 報告
- 見直した章と、直した内容（1 行ずつ）。新しく作った章。直さなかった章とその理由（「文言の変更なし」など）。
